export default async ({ cookies }) => {
  const theme = cookies.get('theme') ?? 'light';
  const user = await cookies.signed.get('user');

  return { theme, user };
};
Call What it does
cookies.get(name) The value, or undefined.
cookies.set(name, value, options) Writes it on the response.
cookies.delete(name) Expires it.
cookies.all() Every cookie, on an object with a null prototype.
cookies.signed.get(name) The value if the signature holds, else undefined.
cookies.signed.set(name, value, options) Signs and writes.

Signing

cookieSecret in the config is what makes cookies.signed work. Without one it throws rather than quietly writing an unsigned cookie. Read it from the environment; where the secret lives is the app's decision. 

// transclude.config.js
export default {
  cookieSecret: globalThis.process?.env?.COOKIE_SECRET ?? null,
};

globalThis.process?.env, not process.env: this file is imported by the worker build too, and a runtime with no Node compatibility has no process. A bare reference throws before anything runs.

A fresh clone should run, so the dev server signs with a random value for that process and prints a notice. Production does not. A server that invented one would invalidate every session on restart and share none with a second instance.

A forged cookie is not a missing one

Absent means no cookie. Present but invalid means somebody changed it. cookies.signed.get turns both into undefined, so ?? fallback cannot sail past the second one.

A flash message

A short-lived signed cookie, read once and then deleted, is the one thing that crosses a redirect exactly once. A message in the URL can be replayed, can be shared, and outlives what it describes. 

const flash = await cookies.signed.get('flash');
if (flash) cookies.delete('flash');
Response.redirect() has headers that cannot be changed, so the envelope copies the response to attach anything the action wrote. Under curl -L the cookie arrives on the next request rather than the followed hop, so check a flash in a browser.
