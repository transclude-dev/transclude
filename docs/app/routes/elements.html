Asking for a shadow root

Export shadow and the element gets a shadow root, a working <slot>, and a re-render when its attributes change.

${html(s.shadow)}
Light, the default shadow = true
Page CSS reaches it Yes Inherited properties and ::part()
<label for> works Yes No
Ships JavaScript Only with behavior Yes
Re-renders on attribute change No Yes
Server-rendered Inline in the page As a declarative shadow root

Stay light unless you need one. A light element is cheaper, your CSS reaches it, and it renders the same way whether the browser asked for a whole page or one fragment of it. Reach for a shadow root when you want the element's styles and DOM sealed off from the page, or when it has to re-render on its own.

Nothing that swaps HTML into a live page builds a declarative shadow root, so an element with one is sent bare in a fragment response and renders itself when it connects. A light element has no such split.

Giving it behavior

A plain <script> block runs once per element. host is the element, shadow is its shadow root or null, and signal aborts when the element leaves the document.

${html(s.behavior)}

A public API

export const prototype puts members on the class. The rest of the block runs once per element.

${html(s.prototype)} host, shadow, signal and internals exist only in the body of the script, which runs once per element. A prototype member is shared by every element of that tag, so it reaches its own element with this. Using host in one is a compile error rather than a bug you find later.

Objects and arrays

Anything that is not a string is written as JSON in the attribute.

${html(s.json)} The JSON sits in the HTML, so it is sent with the document and read back on every attribute change. Pass an id and load the rest in the page's loader rather than putting a large array in an attribute.

An element a form can submit

Export formAssociated and the browser treats it as a form-associated custom element. It needs no shadow root.

${html(s.form)}

Drop it into a form and it behaves like an input. Its value is submitted under its name, and FormData reads it like any other field.

${html(s.formUse)} shadow and formAssociated can go in <script properties> or in <script>, whichever the element already has. Declaring one in both blocks is a compile error. Write true directly rather than a variable: each becomes a static field on the class, the same for every element of that tag.
