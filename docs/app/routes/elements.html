Stay light unless you need one. A light element is cheaper, your CSS reaches it, and it renders the same way whether the browser asked for a whole page or one fragment of it. Reach for a shadow root when you want the element's styles and DOM sealed off from the page, or when it has to re-render on its own.

What each can re-render

Both react to a prop change. A light element writes the text and attributes already in the page, so a node keeps its identity and anything holding a reference to it still does. It never replaces its children: the caller's slotted markup is among them, and the page's script may hold them.

Rebuilding structure needs the boundary. An if or an each over a value that changes is refused in a light element, and the error names shadow.

An element observes its props only once it is defined, and it is defined only with behavior, members, or form association. A light element of plain markup still ships nothing at all.

What <slot> means in each

In a light element the server fills the slot and sends the result. No <slot> reaches the browser: the markup was placed once. Fallback content works, and so do named slots.

In a shadow element the slot is real. The children stay in the light DOM and the browser projects them through it, which is what makes slotchange and assignedNodes() mean something, and what lets content added later find its place.

A declarative shadow root is built when a browser parses a document, so a shadow element arrives bare in a fragment and paints itself on connect. A light element arrives whole.

State

A prop comes from the outside and lives in an attribute. State is the element's own, and nothing outside sets it. <script state> declares it, and each element gets its own copy.

${html(s.state)}

Every name becomes a property on the element. Setting one schedules a re-render, the same as changing an attribute does, and updateComplete resolves once it has been written.

An element a form can submit

Export formAssociated and the browser treats it as a form-associated custom element. It needs no shadow root.

${html(s.form)}

Drop it into a form and it behaves like an input. Its value is submitted under its name, and FormData reads it like any other field.

${html(s.formUse)} shadow and formAssociated can go in <script properties> or in <script>, whichever the element already has. Declaring one in both is a compile error. Write true directly: each becomes a static field on the class.
