// app/routes/api/people.js
import { people } from '../../data/people.js';

export const GET = (ctx) => Response.json(people);

export const POST = async ({ request }) => {
  const body = await request.json();
  people.push(body);
  return Response.json(body, { status: 201 });
};

Uppercase verbs

A page's actions had to be an object because export const delete is a syntax error. export const DELETE is not, so an endpoint exports one per verb. 

export const GET = (ctx) => …;
export const POST = (ctx) => …;
export const DELETE = (ctx) => …;
TypeScript ignores @satisfies on a function declaration, so export const GET = (ctx) => … gets its parameter typed and export function GET(ctx) does not.

It must return a Response

There is no template to fall back to. A handler that returns a plain object has forgotten Response.json.

Helpers

A .js file in routes/ is a route. A helper that lives there needs a _ prefix, or it becomes a URL. 

routes/api/people.js    /api/people
routes/api/_shared.js   not a route
