Sitemap

A hostname mounts /sitemap.xml. Every page route with no parameters is listed, and a parameter route is listed as whatever its paths() export names, which is the same list the build prerenders.

${html(s.sitemap)}

A route with no paths() is left out, because the pattern itself is not a URL. Anything else goes in entries, as an array or a function, and exclude takes a path or a pattern.

${html(s.sitemapEntries)}

Past 50,000 URLs the bare path becomes an index and each ?p= is a slice of the list. Lower limit to see it on a small site.

Feeds

A sitemap comes from the route table, because a URL is all it lists. A feed needs a title, a date and something to read, so the items are yours to pass in.

${html(s.feed)}

That mounts /feed.xml as RSS 2.0. Each item needs a title and a path. date, description, content and author are optional, and content is where full HTML goes.

Items are published newest first and capped at 50. Set limit for a different number.

Atom

format: 'atom' writes Atom 1.0 instead. The spec requires an author and a date, so the feed needs an author or every item needs its own, and at least one item needs a date.

${html(s.atom)} Nothing here reads the clock. The feed is stamped from the newest item it holds, so a build that changes nothing writes the same bytes, and a prerendered feed can be compressed once and cached like any other file. A feed whose items have no dates can set updated itself.

Where they end up

Both are served by the app and both are written into dist/static by the build. A host serving the directory has them without running anything.
