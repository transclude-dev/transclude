Your own pages mark a fragment with an attribute, and the compiler emits a render function for it. See fragments. None of that is available in a document somebody else wrote, so this is a separate thing with separate rules.

Turning it on

There is no route until a host is named. Default deny, and the list is the part that actually protects you.

${html(s.config)} ${html(s.request)}

With no id, the answer is the document's outline.

${html(s.outline)}

Including one in a page

${html(s.include)}

The children are the fallback. On success they are dropped; if the source cannot be read, they render in place of it. An element with no children whose source fails stops the render, because a hole nobody wrote looks like content.

Includes are resolved before the page renders, not during it. That is what lets a prerendered page carry the result: it reads the source once, at build time, and is written to a file like any other page. Several includes are resolved together, and several from one document cost one read.

src="#pricing" includes a region of the page it sits in. That one is free: the region is already compiled to a function, so nothing is fetched and nothing is parsed. ${html(s.same)} The copy leaves the id behind. A region keeps its name where it is declared, which is what a swap replaces.

How extent is worked out

An id says what a thing is, not where it ends. Only what HTML already encodes is used:

  • A heading takes everything after it up to the next heading of its own rank or above. An h2 absorbs its h3s; an h3 stops at the next h3 or any h2. A run never crosses out of its parent.
  • A <dt> takes its definitions up to the next term.
  • Everything else is returned as itself, with no inference at all.

An empty inline element is read as a bookmark for what follows it, which is how anchors were written before ids went on headings. <a id="install"></a><h2>Installing</h2> resolves the heading. One hop only, and an element holding text or an image is content rather than a bookmark.

A document with no ids is still addressable: a heading with no id gets one from its text. Explicit ids always win, and the whole table is worked out before anything is resolved, so a name means the same thing on every request.

A heading run is several siblings, not one element. It is returned as it appears in the source, with no wrapper added, because a wrapper would mean the fetched markup no longer matched the page it came from.

What arrives

Scripts, frames, plugins and event handlers are removed. javascript: URLs go everywhere; data: survives only on an image source. <base> and <link> are removed too: the first would retarget every relative URL in your page, and the second can pull a stylesheet from anywhere.

Every relative URL is made absolute against the source, including a hash-only href, which would otherwise address an id in your page. srcset is parsed rather than split on commas, since a URL may contain one, and url() is rewritten in style attributes and style blocks.

Limits

${html(s.tuning)}

Redirects are followed one at a time and every hop is checked again, because the check that passed on the URL you configured says nothing about where the third redirect landed. Addresses on the private ranges are refused, including the cloud metadata endpoint and IPv4 addresses written in IPv6 form.

On Node and Deno a hostname is resolved and every address it answers with is checked. Cloudflare Workers has no resolver, so there that check does not run and the allowlist is the whole defense. Name hosts you trust, and treat a wildcard as trust in everything under it.

Why it goes through your server

The fragment is resolved here rather than in the browser. The page receives the piece it asked for instead of a whole foreign document, sanitizing happens somewhere it cannot be switched off, and the request is same-origin, which the default policy requires: it names 'self' and a cross-origin fetch is refused.
