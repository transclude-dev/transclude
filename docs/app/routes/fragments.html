Add an id and a fragment attribute. The element renders in the page as usual, and the same path with ?fragment= and that id returns just that element.

${html(s.markup)}
Request Response
GET /?q=ada the whole document
GET /?q=ada&fragment=matches the <div> and its contents
GET /?fragment=nope 404

The id is the name. The URL asks for matches and a swap targets #matches.

What they are for

Anything on a page that changes while the rest stays put: search results as you type, a list after something is added to it, the next page of a table. Fetch that one element and replace the copy in the page with it, instead of loading the whole document again.

The page and the fragment come from one compiled template, so the two always agree.

Asking for one

A fragment is an ordinary URL. Anything that fetches HTML can use it.

${html(s.fetch)}

htmx does the same with attributes. Turbo and htmz are other options.

${html(s.htmx)}

htmx sends the target's id in an HX-Target header. Name that header in the config and the query parameter becomes optional.

${html(s.header)}

htmz

htmz swaps with no fetch. A hidden iframe loads the URL and one line of script moves what came back into the page. A URL hash is never sent to a server, so it is free for the client to use, and htmz reads it as the destination.

${html(s.htmz)}

The query asks this app for a fragment. The hash says where it goes. Neither half knows about the other, so nothing here is a framework feature.

htmz replaces the destination element, and a fragment arrives carrying its own id. Send matches to #results and the page ends up with #matches where #results was, so the next click finds nothing and does nothing. Point the hash at the fragment's own name.

The published snippet puts its handler in an onload attribute. Turn on the policy and that handler is refused: it hashes script blocks, and a hash never covers an attribute. The swap then never happens and nothing on the page says why. Assign the handler in a script block instead and it is hashed like any other.

${html(s.trampoline)}

With no JavaScript a link that targets the frame loads into it and the visitor sees nothing. Add target from a script if the page has to work without one.

Includes put a fragment in a second place on the server.

setHTMLUnsafe() builds shadow roots from the markup it is given. A shadow element in a fragment needs it to start up.

Swapped-in markup styles itself

A fragment can land on a page that never rendered the elements inside it. Those elements have no definition there and no styles. Set watchElements and every page carries a small script that notices a new tag, loads its definition and adds its styles once.

It is off by default, because it puts that script on every page and only earns it when swaps really do bring in elements the page did not already render. This site does not turn it on.

The parameter is strict, the header is not

?fragment=nope is a 404. Someone wrote that name into a URL, so getting it wrong should say so.

A header naming a fragment is a hint, and an unknown name is ignored. Client libraries send these headers on every request, including ones that want a whole document. HX-Target from htmx works this way.

Naming a header in fragmentHeader adds it to Vary.

Actions

POST /?fragment=nope changes nothing and returns 404. The fragment is checked before the action runs.

ctx.fragment tells a form submission from a fetch. The first wants a redirect, the second wants markup.
