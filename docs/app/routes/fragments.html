Add an id and a fragment attribute. The element renders inside the page as usual, and you can also request it on its own at the same path with ?fragment= and that id.

${html(s.markup)}
Request Response
GET /?q=ada the whole document
GET /?q=ada&fragment=matches the <div> and its contents
GET /?fragment=nope 404

The id is the name. The URL asks for matches and a swap targets #matches.

What they are for

Anything on a page that changes on its own: search results as you type, a list after something is added to it, the next page of a table, a panel that refreshes on a timer. Ask for that one piece and put it back in place.

The markup is compiled once, so what comes back matches what a full page load would have rendered. There is no second template to keep in step. This is transclusion, which is where the framework gets its name.

Asking for one

A fragment is an ordinary URL, so anything that can fetch HTML and put it in the page will do.

${html(s.fetch)}

Libraries built for this do the same thing with attributes instead of script.

htmx is the common one.

To put a region in a second place on the server instead, without anything swapping it in, see includes.

${html(s.htmx)}

htmx sends the target's id in an HX-Target header. Name that header in the config and the query parameter becomes optional.

${html(s.header)}

Turbo and htmz are other options.

setHTMLUnsafe() builds shadow roots from the markup it is given. innerHTML skips them, so a shadow element inside the fragment would arrive without its contents and never start up.

Swapped-in markup styles itself

A fragment can land on a page that has never rendered the elements inside it. While fragmentParam is set, every page includes a small script that notices an unknown tag, loads its definition and adds its styles once. There is nothing to wire up.

Set fragmentParam: null and a page ships exactly what it renders. This site is built that way.

The parameter is strict, the header is not

?fragment=nope is a 404. Someone wrote that name into a URL, so getting it wrong should say so.

A header naming a region is a hint, and an unknown name is ignored. Client libraries set these headers on every request they make, including the ones that want a whole document, so refusing an unrecognized name would break more than it fixed. HX-Target from htmx works this way.

Naming a header in fragmentHeader adds it to Vary.

Actions

POST /?fragment=nope changes nothing and returns 404. The fragment is checked before the action runs.

ctx.fragment tells a form submission from a fetch. The first wants a redirect, the second wants markup.
