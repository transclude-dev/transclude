Add an id and a fragment attribute. The element renders in the page as usual, and the same path with ?fragment= and that id returns just that element.

${html(s.markup)}
Request Response
GET /?q=ada the whole document
GET /?q=ada&fragment=matches the <div> and its contents
GET /?fragment=nope 404

The id is the name. The URL asks for matches and a swap targets #matches.

What they are for

Anything on a page that changes on its own: search results as you type, a list after something is added to it, the next page of a table. Ask for that piece and put it back in place.

The page and the fragment come from one compiled template, so the two always agree.

Asking for one

A fragment is an ordinary URL. Anything that fetches HTML can use it.

${html(s.fetch)}

htmx does the same with attributes. Turbo and htmz are other options.

${html(s.htmx)}

htmx sends the target's id in an HX-Target header. Name that header in the config and the query parameter becomes optional.

${html(s.header)}

Includes put a region in a second place on the server.

setHTMLUnsafe() builds shadow roots from the markup it is given. A shadow element in a fragment needs it to start up.

Swapped-in markup styles itself

A fragment can land on a page that never rendered the elements inside it. While fragmentParam is set, every page carries a small script that notices a new tag, loads its definition and adds its styles once.

Set fragmentParam: null and a page ships exactly what it renders. This site is built that way.

The parameter is strict, the header is not

?fragment=nope is a 404. Someone wrote that name into a URL, so getting it wrong should say so.

A header naming a region is a hint, and an unknown name is ignored. Client libraries send these headers on every request, including ones that want a whole document. HX-Target from htmx works this way.

Naming a header in fragmentHeader adds it to Vary.

Actions

POST /?fragment=nope changes nothing and returns 404. The fragment is checked before the action runs.

ctx.fragment tells a form submission from a fetch. The first wants a redirect, the second wants markup.
