A region of this page

The region is already compiled to a function of the page's data, so including it is calling that function. Nothing is fetched, nothing is parsed, and there is one copy of the markup rather than two that could drift.

${html(s.same)} ${html(s.sameOut)}

The copy leaves the id behind. A region is always rendered where it is declared, so an include is always a second copy in the same document, and two elements cannot share an id. The one that keeps the name is the one a swap aimed at #pricing should find.

A region of another route

${html(s.route)}

Rendered rather than fetched. It is the same process, so a request to ourselves would run the whole middleware stack to answer something we can answer directly. That route's loaders run and its layouts' markup does not, the same as when a region is asked for over HTTP. One route included twice runs its loaders once.

The included route reads cookies through the including page's own, so a page that includes a route reading a cookie is personal too and the cache will not hold it. Without that the second visitor is handed the first one's page. For the same reason the build refuses to write a prerendered page that read a cookie, whether the page read it or something it includes did.

A document somebody else wrote

${html(s.site)}

The only form that leaves the server, and the only one that needs configuring. A page you did not write marks no regions, so which piece to take is worked out from what HTML already encodes. That is the second half of this page.

Children are the fallback

On success they are dropped. If the source cannot be read they render in its place. An element with no children whose source fails stops the render, because a hole nobody wrote looks like content.

A source that is unreachable falls back. A source that was never configured, or an include that goes round in a circle, is thrown instead: those are mistakes rather than conditions, and the fallback would hide them.

Resolved before the page renders

Not during it. Rendering is synchronous the whole way down, and reading another document is not, so what a page declares is collected when it is compiled and the server has the answers ready before it renders.

That is what keeps a page a file. A prerendered page reads its sources once, at build time, and carries the result. A page that fetched while rendering could never be written down.

What is refused

${html(s.refused)}

All three are compile errors. A page that includes itself round two others is caught when it renders, with the way round named, and so is a chain more than ten deep.

An include is resolved once, before the markup leaves the server. There is no element here that fetches one in the browser: a region has a plain URL, and htmx, Turbo or a short fetch is what asks for it. See fragments.

Reading a document that marks nothing

Everything above works because your own pages say what a region is. A page somebody else wrote says nothing of the kind, so the rest of this is how a piece of one is found, and how it is made safe to show.

Turning it on

There is no route until a host is named. Default deny, and the list is the part that actually protects you.

${html(s.config)}

How extent is worked out

An id says what a thing is, not where it ends. Only what HTML already encodes is used:

  • A heading takes everything after it up to the next heading of its own rank or above. An h2 absorbs its h3s; an h3 stops at the next h3 or any h2. A run never crosses out of its parent.
  • A <dt> takes its definitions up to the next term.
  • Everything else is returned as itself, with no inference at all.

An empty inline element is read as a bookmark for what follows it, which is how anchors were written before ids went on headings. This resolves the heading and its section, not the empty anchor.

${html(s.bookmark)}

One hop only, and an element holding text or an image is content rather than a bookmark.

Documents with no ids

A heading with no id gets one from its text, lowercased, punctuation removed, spaces hyphenated. Letters keep their own script rather than folding to ASCII.

Explicit ids always win, and the whole table is worked out before anything is resolved. A generated name cannot depend on which fragment was asked for, so an id further down the page still beats a heading further up, and the heading takes the next name instead.

A heading run is several siblings, not one element. It is returned as it appears in the source, with no wrapper added, because a wrapper would mean the fetched markup no longer matched the page it came from.

What arrives

Scripts, frames, plugins and event handlers are removed. javascript: URLs go everywhere; data: survives only on an image source. <base> and <link> are removed for your page's sake rather than the fragment's: the first would retarget every relative URL in the document the fragment lands in, and the second can pull a stylesheet from anywhere.

Every relative URL is made absolute against the source, including a hash-only href, which would otherwise address an id in your page. srcset is parsed rather than split on commas, since a URL may contain one, and url() is rewritten in style attributes and style blocks.

A custom element from the source arrives as markup with no definition behind it. It is inert rather than broken, but a section built out of them will look empty.

Limits

${html(s.tuning)}

Redirects are followed one at a time and every hop is checked again, because the check that passed on the URL you configured says nothing about where the third redirect landed. Addresses on the private ranges are refused, including the cloud metadata endpoint and IPv4 addresses written in IPv6 form.

maxAge is how long a document already read is used without asking the source anything, so several fragments of one page cost one read. After that it is revalidated with ETag and Last-Modified.

On Node and Deno a hostname is resolved and every address it answers with is checked. Cloudflare Workers has no resolver, so there that check does not run and the allowlist is the whole defense. Name hosts you trust, and treat a wildcard as trust in everything under it.

The endpoint

Naming a host also mounts /_transclude/proxy, which is what a client library would ask if you drive an include yourself.

${html(s.request)}

With no id, the answer is the document's outline.

${html(s.outline)}

The fragment is resolved on this side rather than in the browser. The page receives the piece it asked for instead of a whole foreign document, sanitizing happens somewhere it cannot be switched off, and the request is same-origin, which the default policy requires: it names 'self' and a cross-origin fetch is refused.
