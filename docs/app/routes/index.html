transclude

HTML is the product.

You write a page as an .html file. The server renders it and sends back plain HTML. There is no client framework to start up, and nothing has to run before the page works.

Your folder structure is your routing. A page handles GET. Export POST from it to handle a form. Put a .js file in the same folder and it becomes an API endpoint. Hono runs the server.

It is HTML-first and hypermedia-driven. The markup the server sends is the state of your app, and links and forms are what change it. If that idea is new to you, Hypermedia Systems is a good place to start.

This site is built with it. Every page you are reading is one .html file in docs/app/routes/.

Everything in one file

Data loading, markup, styles and behavior live together in the file the URL points at.

Fetch any part of a page

Give an element an id and you can request just that piece, from the same compiled markup.

Partials before components

A partial is plain HTML inside your page. Your CSS reaches it and it ships no JavaScript.

Runs anywhere

Node, Bun, Deno and Cloudflare Workers, from the same code.

Where the name comes from

Transclusion means putting part of one document inside another by pointing at it, instead of copying it. Ted Nelson named the idea in Literary Machines, the book that described his Project Xanadu. He had already given us the word hypertext.

This framework does it twice. A partial is markup pulled into the page that calls it. A fragment is a piece of a page that keeps a URL of its own, so you can render it in place or fetch it by itself. Either way there is one copy of the markup.
