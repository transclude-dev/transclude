The page renders into <slot>. Name a slot to offer more than one.

${html(s.named)}

Nesting

A _layout.html in a subdirectory renders inside the one above it. Put a nav in the root layout and a sidebar in the section layout, and a page in that section gets both.

${html(nested)}

Each one loads its own data, and each gets its own <slot> filled by whatever is below it.

A layout can respond on its own

Return a Response from a layout loader and it stops there. Nothing below it runs, which is how you write a login redirect once.

${html(s.guard)} A page behind a guard needs export const prerender = false. Otherwise the build writes a logged-out copy to a file.

Attributes on <html>

The root layout owns the document, so it is where a theme or a text direction belongs. Write <html> and its attributes become the document's, the same way a <title> anywhere in the chain becomes the document's title.

${html(s.htmlAttrs)}

They merge by name along the chain, innermost winning, so a root layout can set the theme and a page can set dir. Values are escaped, a bare attribute is true, and false or null drops it. lang is there already and can be overwritten.

Sharing the response

Every loader in the chain holds the same ctx.response, so a layout that sets a status sets the one the server sends.
