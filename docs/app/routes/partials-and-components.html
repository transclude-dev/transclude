Partial Component
Lives in partials/ components/
Boundary None. Light DOM. Shadow root.
Page CSS reaches it Yes Only inherited properties
<label for> works Yes No
Ships JavaScript Only with behavior Yes
Re-renders on attribute change No Yes

Reach for a partial first. It is the cheaper of the two and covers most reuse. Choose a component when you want its styles and DOM sealed off from the page, its markup and behavior kept together in one file, and the same tag usable anywhere without the page knowing how it works.

A partial

The file name is the tag name.

${html(s.partial)} ${html(s.use)}

The style block is hoisted into <head> once, however many times the partial appears.

Giving it behavior

A plain <script> block runs once per element. host is the element, shadow is its shadow root or null, and signal aborts when the element leaves the document.

${html(s.behavior)}

A public API

export const prototype puts members on the class. The rest of the block runs once per element.

${html(s.prototype)} host, shadow, signal and internals exist only in the body of the script, which runs once per element. A prototype member is shared by every element of that tag, so it reaches its own element with this. Using host in one is a compile error rather than a bug you find later.

A component

The same file shape, in components/. You get a real Web Component: a shadow root, a working <slot>, and a re-render when its attributes change.

${html(s.component)}

Objects and arrays

Anything that is not a string is written as JSON in the attribute.

${html(s.json)} The JSON sits in the HTML, so it is sent with the document and read back on every attribute change. Pass an id and load the rest in the page's loader rather than putting a large array in an attribute.

A component a form can submit

Export formAssociated from the element's <script> block and the browser treats it as a form-associated custom element. Write true directly rather than a variable, because it becomes a static field on the class and is the same for every element of that tag.

${html(s.form)}

Drop it into a form and it behaves like an input. Its value is submitted under its name, and FormData reads it like any other field.

${html(s.formUse)}

A partial can do this too. Being a form control needs no shadow root.
