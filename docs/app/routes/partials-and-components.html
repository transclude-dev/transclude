Lives in partials/ components/
Boundary None. Light DOM. Shadow root.
Page CSS reaches it Yes No, only inherited properties
<label for> works Yes No, ids are scoped
Ships JavaScript Only if it declares behavior Yes
Re-renders on attribute change No Yes

Reach for a partial first. A component answers a narrower question than most pages ask, and it is what makes an element survive being moved around a live page.

A partial

<script properties>
  export default {
    tone: 'neutral',
  };
</script>

<style>
  /* Hoisted into <head> once, however many times this appears. */
  :scope {
    display: block;
    border-left: 3px solid var(--rule);
    padding: 0.5rem 0.9rem;
  }
  :scope[tone='warn'] {
    border-color: #b4232c;
  }
</style>

<p><slot>Nothing to say.</slot></p>

Used as an element, with its props as attributes.

<site-note tone="warn">A partial, in the page's own DOM.</site-note>

Giving it behavior

A plain <script> block runs once per element. host is the element, shadow is its shadow root or null, and signal aborts when the element leaves the document. 

<script>
  // A listener given the signal removes itself. Nothing has to name the
  // teardown, and nothing can forget it.
  document.addEventListener(
    'keydown',
    (event) => {
      if (event.key === 'Escape') host.dismiss();
    },
    { signal },
  );
</script>

A public API

export const prototype puts members on the class, shared by every element of that tag. The rest of the block runs once per element, so where a declaration sits decides its lifetime. 

export const prototype = {
  dismiss() {
    this.hidden = true;
    this.dispatchEvent(new CustomEvent('dismiss', { bubbles: true }));
  },
};
host, shadow, signal and internals belong to one element. Reading one from a prototype member is a compile error rather than a value shared without anyone asking.

A component

The same file shape, in components/. It gets a shadow root, a real <slot>, and it re-renders when its attributes change. 

${component}

An object or array prop is written as JSON in the attribute, and read back as a value.

A component a form submits

export const formAssociated = true makes the browser treat the element as a field. It has to be a literal, because it becomes a static class field and is the same for every element of that tag. A partial can opt in too; being a form control needs no shadow root.

The value is reported at the top of the attribute change, before the render, so what a form submits matches what the DOM already says.
