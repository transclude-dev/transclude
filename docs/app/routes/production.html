Prerendering

Every static route is rendered to a file. A page that reads the request needs to say so, or the one file written for it becomes the answer to every URL that resolves there. 

export const prerender = false;

A page reading ?q, a page behind a guard, and a page whose data changes are all in that group.

Compressed at rest

Build output is compressed once, at build time, and each encoding gets its own strong ETag. A revalidating client pays for a hash and nothing else.

What Cache-Control
Hashed assets public, max-age=31536000, immutable
Prerendered pages public, max-age=0, must-revalidate
The 500 page no-store, and no ETag

Public files

app/public/ is copied to dist/public and served by Hono's static middleware, not from the in-memory cache the build output uses. These files belong to the app, can be large, and can be media. Media needs byte ranges, and the in-memory path answers 200 where a 206 was asked for.

Error pages

404.html and 500.html are prerendered and sent as bytes. They are reached for, not routed to: a page that has to be rendered when a request has already failed can fail too.

Production logs the throw and sends the 500 page without putting the error in the body. Dev sends the stack instead, which is what you want when you are the one fixing it.

A page ships a client entry only if something on it needs one. One rule decides, read by both the dev server and the build, so a page cannot get an entry in one and not the other.
