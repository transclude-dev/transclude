Give an element an id and a fragment attribute. It renders in the page, and it answers on its own at the same path with ?fragment= and that id.

${html(s.region)}
Request Response
GET /?q=ada the whole document
GET /?q=ada&fragment=matches the <div> and its contents
GET /?fragment=nope 404

The id is the name. The URL asks for matches and a swap targets #matches.

Swapping is somebody else's job

This framework ships nothing that swaps a region into a page. A region has a plain HTTP URL. htmx, Turbo or a short fetch drives it.

${html(s.swap)} innerHTML does not process nested declarative shadow roots, so a component inside the region arrives as a dead <template>.

What a page carries

With fragmentParam set, every page carries a small loader that watches for a tag it never rendered. Markup swapped in from another route defines and styles itself.

Set fragmentParam: null and a page ships exactly what it renders. This site is built that way.

The parameter is strict, a header is a hint

  • ?fragment=nope is a 404.
  • HX-Target: nope is ignored. htmx sends that header on every request, including ones that want the whole document.

Setting fragmentHeader adds that header to Vary.

Actions and regions

POST ?fragment=nope changes nothing and returns 404. The region is checked before the action runs.

ctx.fragment tells a form submission from a client fetching a piece. The first wants a redirect, the second wants markup.
