Give an element an id and a fragment attribute. It renders in the page as part of the document, and it answers on its own at the same path with ?fragment= and that id. 

${region}
Request Response
GET /?q=ada the whole document
GET /?q=ada&fragment=matches the <div> and its contents
GET /?fragment=nope 404

There is one compiled region, so the piece that gets swapped in cannot drift from the page it replaces part of. The id is the name: the URL asks for matches and a swap targets #matches.

Swapping is somebody else's job

This framework ships nothing that swaps a region into a page. A region has a plain HTTP URL, and that is the whole agreement. htmx, Turbo or a short fetch drives it. 

const res = await fetch('/?q=ada&fragment=matches');
document.getElementById('matches').setHTMLUnsafe(await res.text());
innerHTML does not process nested declarative shadow roots, so a component inside the region arrives as a dead <template>.

What the page does carry

With fragmentParam set, every page carries a small loader that watches for a tag it never rendered. Markup swapped in from another route defines and styles itself, whoever put it there. That is the one piece a client library cannot do for itself.

Set fragmentParam: null and no page carries anything. A page then ships exactly what it renders, which is the content-site case. This site is built that way.

The parameter is strict, a header is a hint

  • ?fragment=nope is a 404, because somebody typed it and should be told it is wrong.
  • HX-Target: nope is ignored, because htmx sends that header on every request, including ones that want the whole document.

Turning on fragmentHeader also adds that header to Vary, which is why it is off by default. A cache key is a bad thing to widen for a feature an app may not use.

Actions and regions

A region is checked before an action runs, so POST ?fragment=nope changes nothing and then 404s. Anything that can refuse a request refuses it first.

ctx.fragment is how an action tells a browser submitting a form from a client fetching a piece. The first wants a redirect, the second wants markup.
