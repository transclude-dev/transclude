The loader

A <script server> block runs on the server. Its default export takes the request context and returns the data the markup reads. 

${loader}

What the context holds

Field What it is
params The path segments this route captured.
url The full URL as a string. null while prerendering.
route The matched route, including its path.
action What this page's action returned, if one ran.
fragment The region asked for, or null for a whole document.
cookies Read and write, signed or plain.
response The status and headers this request will answer with.

Returning a Response

A loader that returns a Response answers the request, and the render never runs. It is the same rule an action has, so there is one rule rather than two. 

export default async ({ params }) => {
  const person = find(params.name);
  if (!person) return new Response('no such person', { status: 404 });
  return { person };
};

Status and headers

ctx.response is one object shared by every loader in the chain and by the server. Writing to it is how a page answers with something other than 200. 

export default async ({ params, response }) => {
  const person = find(params.name);
  if (!person) response.status = 404;
  return { person };
};

Directives

Attributes on an element, read as expressions rather than as strings. There is no ${empty} inside one. 

${directives}

key tells the browser which item is which when a list is re-rendered, so input values and focus survive a reorder.

A template expression is not a whole language, on purpose. Sorting, filtering and formatting are the loader's job.
