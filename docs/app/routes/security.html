That is the whole setup. Each page gets a policy built from what that page inlines, and CSRF is already on by default.

Escaping

Every \${…} is escaped. A value carrying markup arrives as text, so a page rendering something a visitor typed cannot run it.

${html(s.escaped)} ${html(s.escapedOut)}

html() turns that off for one value. It is a claim that the markup is yours: rendered Markdown you control, or output a library you trust produced.

${html(s.trusted)} html() sanitizes nothing. Wrapping anything a visitor typed is how a page runs somebody else's script, and no Content-Security-Policy below will save you: the script came from your own origin, in your own document.

HTML is parsed before any interpolation runs, so a value cannot open or close anything structural. Markup arriving through html() lands inside whatever element already surrounded it, and a comment ends where the file ends it.

${html(s.parseOrder)}

Hashes, not a nonce

A nonce is a fresh random value per request, named in the policy and stamped on every inline block. It cannot work here: a page carrying one is different on every request, and most pages here are files, rendered and compressed once at build time.

A hash is fixed when the page renders. It is written into the file, stays correct, and a host that has never heard of this framework serves it unchanged.

${html(s.output)} You do not stamp anything. The policy is built from the document after it renders, so it names what actually shipped rather than what was meant to.

Why styles are not hashed

script-src carries hashes and style-src does not. That looks inconsistent and is the only combination that works.

A hash never covers an attribute. style="color:red" on an element is checked against style-src, and a hash there applies to <style> blocks only. Adding 'unsafe-inline' alongside does not help either: a directive carrying any hash ignores 'unsafe-inline' outright. So hashing styles means no element on the page may carry a style attribute, and style="view-transition-name: …" is an ordinary thing to write.

Script is where the protection matters, and CSS cannot run code. Put 'hashes' in style-src yourself if your pages have no style attributes at all.

Directives sent as a header

frame-ancestors, report-uri, report-to and sandbox are ignored in a <meta> tag, so they are sent as a response header instead. None of them names a hash, so that header is the same for every page and costs a prerendered one nothing.

A static host serves the meta half and not the header. Set those directives at the host if you export the site and need them.

Your own directives

Pass directives to replace the defaults. 'hashes' in a source list is where that page's own digests go, so you decide which directives get them.

${html(s.custom)}

A directive left with no sources is dropped rather than written empty, since an empty list means 'none' and saying that by accident breaks the page rather than protecting it.

Report before you enforce

The browser reports what would have been blocked and blocks nothing, so a policy can be tightened against real traffic first.
