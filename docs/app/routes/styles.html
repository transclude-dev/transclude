What crosses a boundary

  • Custom properties inherit, so --rule on :root reaches inside a shadow root.
  • Selectors do not. A global class lands on a page and on a light element, and stops at a shadow root.

So a global stylesheet themes a shadow element through custom properties. To let it style something inside, the element marks that node with a part attribute, which ::part() then selects. The element decides what it exposes.

Styles in a file

A <style> block in a page or layout is hoisted into <head>. In an element it is scoped to that tag, and :scope is how you style the element itself.

${html(s.scoped)}

Styles for swapped-in markup

An element that arrives with a fragment brings its styles with it. They are added to <head> once, on their own. There is nothing to set up.

The element itself

A light element is styled with :scope, a shadow one with :host. Both mean the same thing: the element this stylesheet belongs to.

${html(s.selectors)}

They differ in what can reach them. :scope rules are hoisted into <head> and lose to page CSS of equal specificity, so a page can override a light element it did not write. :host lives inside the shadow root and page CSS cannot reach it at all, though :host itself has very low specificity, so a rule inside the element beats it.

View transitions

Cross-document view transitions are CSS-only and opt-in. Both documents must carry the rule.

${html(s.transition)}

A name has to be unique in a document. Derive one from the data when the same element appears in a list and on a detail page.
