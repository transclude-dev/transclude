npm run check

With no annotations at all it still catches a misspelled field in a template, an unknown prop on a component, and a prop given the wrong type. Those come from what the loader returns and what <script properties> declares.

strict: true in the config turns on full TypeScript strictness, which additionally wants a declared type on every parameter.

Where the types come from

  1. What the loader's return value infers to.
  2. What <script properties> declares for a component.
  3. JSDoc, where inference is not enough.
<script server>
  /** @param {{ params: { name: string } }} ctx */
  export default async ({ params }) => {
    return { name: params.name };
  };
</script>

Attributes that are not props

hx-*, data-* and aria-* pass through. They are still checked as expressions, but the claim that the name was declared goes away, so ${passThrough} on a component is not a type error for a page that works.

transclude-env.d.ts

Generated from the compiled routes and written where typesFile says. It is an output, so it belongs in .gitignore and is rebuilt by transclude-check.
