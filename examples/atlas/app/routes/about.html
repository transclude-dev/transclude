About

Every repository on the AT Protocol is public. This reads them, renders each record from the schema its own author published, and shows the path it took to get there.

Every view has a URL of its own

A record page is a page. It is also a fragment, which means the record on it answers to an address by itself:

  • /at/<uri> — the record, in this site
  • /embed/<uri> — the same record, with no navigation
  • /embed/<uri>?fragment=record — that markup and nothing else

All three come from one template, so an embed can never disagree with the page it came from.

Putting one on your page

This is HTML, not an iframe. Your stylesheet reaches it, it selects and copies like the rest of your text, and it needs no JavaScript.

On another transclude site, the server does it:

${server}

with the host named once, in your config:

${allow}

Anywhere else, fetch the fragment:

${client}

When the record is gone

An embed outlives the record it points at. A post from last year should not leave a hole in an article, so /embed/ always answers with something you can put on a page: the record if it is there, and a note saying what was asked for and what happened to it if it is not.

Limits

  • Read only. This writes nothing and asks you to sign in to nothing.
  • Media is linked to the server that holds it, never copied here. Images on a record page come from its author's PDS.
  • Cached for five minutes, and served stale for a day after that while it refreshes. Embeds send other people's readers at other people's servers, and that is the part of this to be careful with.
  • did:plc and did:web resolve. Other DID methods say so rather than guessing.
