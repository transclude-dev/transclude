Elements

An .html file in app/elements/ is a custom element. It renders into the page's own DOM unless it asks for a shadow root, and the file says which.

Light, and shipping nothing

site-note has styles, a slot and no behaviour. It is rendered on the server and defines no class in the browser, so it costs a visitor nothing.

Page CSS reaches this, which is what makes it content. The same element, one attribute apart.

Light, and interactive

tally-box has state and behaviour, and is still light. Clicking it writes a new number into the text node the compiler bound. Nothing is replaced, which is exactly what a light element is allowed to do.

Both boxes count separately. State belongs to an element, not to the tag.

Shadow, and rebuilding

person-card asks for a boundary. Its styles cannot leave and page CSS cannot reach in, so its rules name h3 and mean it. It also renders a list from a prop that can change.

Which one

Stay light. Reach for the boundary when one of these is true.

Light Shadow
Page CSS styles it, which is right for content Styles are sealed, which is right for a widget
<label for> and a form find it A form needs formAssociated
Writes into what it rendered Rebuilds, so if and each over changing data work
Arrives whole in a fragment Arrives bare in a fragment, and paints on connect
An if or an each over a value that changes is a compile error in a light element, and the message names shadow. It is not a limitation being enforced for tidiness: a light element does not own its children, and the page's markup and scripts are sitting among them.
