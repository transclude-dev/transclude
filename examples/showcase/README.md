# The showcase

Every feature the framework has, and the browser checks. `transclude` is a
dependency here, from `file:../..`, so this is an ordinary app that happens to
live in the framework's repository. Editing the framework shows up in the next
`npm run dev` with no publish step in between.

```
npm install
npm run dev       # http://localhost:1961
npm run preview   # build, then serve on http://localhost:1961
npm run check     # tsc over every .html and .js route
npm test          # 29 tests, about this app's own files
```

`COOKIE_SECRET` goes in `.env`. Copy `.env.example`. Without it the dev server
signs with a random per-process value and says so. Production refuses.

## What is here

```
transclude.config.js   where the app is. The whole interface to the framework
worker.js              the workerd entry, wiring transclude/worker
wrangler.jsonc         points at worker.js
vite.config.js         the framework's plugin, nothing else
test/                  the build output, the worker entry, the config

app/
  routes/              pages, endpoints, layouts, the 404 and 500
  server.js            this app's own Hono middleware
  public/              served as-is at the root: favicon, robots.txt, theme.js
  partials/            light DOM, @scope styles
  components/          shadow DOM, with their own boundary
  styles/global.css    tokens, reset, base typography. One linked file
  data/                plain modules the loaders import
  transclude-env.d.ts  generated by npm run check
```

## The pages

| | |
| --- | --- |
| `/` | cards, a partial, and a region asked for on its own URL |
| `/notes` | a form. POST, change the data, 303, render. Works with JavaScript off |
| `/people/:name` | a dynamic route with a layout above it |
| `/docs/*` | a catch-all, and the one route the server still renders per request |
| `/api/people` | an endpoint: a `.js` file in the routes tree |
| `/check` | the browser checks |

## The browser checks

`/check` is 53 assertions that only a browser can answer. They run a classic
inline script while the page is parsing, before any module runs, so they can look
at the document before a single component is defined.

All 53 pass in Chrome 150, Safari 26.4 and Firefox 152.

Open `/check?report` and the run is posted to `/api/checks`, which prints it in
the server log. That is how Safari and Firefox were measured: neither can be
driven from a shell without setup, since Safari needs "Allow remote automation"
turned on by hand and Firefox needs geckodriver installed. Posting the results
needs neither, and it works in any browser.

These checks are the framework's only browser coverage. They live here because
they need an app to run against.

## Four runtimes

```
npm start             Node
npm run start:bun     Bun
npm run start:deno    Deno
npm run start:worker  workerd, through wrangler dev
```

All four answer the same way over ten routes: same 301 on a trailing slash, same
403 on a forged cross-origin post, same `Set-Cookie`, same 304. The one
difference is that a worker serves no byte ranges, because those need a
filesystem.

## Known limits

- The notes live in memory and reset on restart. Storage is not the point of the
  demo, but it does mean a restart looks like data loss.
- In dev, Vite logs `Failed to load url /theme.js` on every page load. The file
  exists and Hono serves it. Vite warms up every module script tag in the served
  HTML and does not own that one. There is no way to turn the warning off without
  letting Vite serve the public directory, which is the split between dev and
  production that this avoids.
- `wrangler dev` is workerd locally. Nothing here has been deployed to an edge,
  so the runtime is verified and the platform is not.
