innerHTML leaves a dead template

A declarative shadow root is markup. It arrives in the response, the parser reads it, and the component is styled and correct before any JavaScript runs. That is the whole appeal of it.

Then you swap a piece of the page, and the same markup does nothing.

What the server sends

${html(s.fragment)}

One element, on its own URL, with a component inside it. Ask for that on a full page load and the browser gives note-card a shadow root built from the template. The border is drawn and the slot is filled.

What the swap does to it

${html(s.swap)}

Two lines, and the card is dead. note-card is in the DOM. So is the <template>, sitting inside it as an ordinary element that renders nothing. card.shadowRoot is null. The style never applies, and the text meant for the slot sits in the page with no <article> around it.

Nothing throws. The console stays empty. The markup in devtools is the markup you sent, which is what makes this one expensive to find.

The parser decides, not the markup

Declarative shadow roots are a parser feature, and each way into the parser chooses whether to honor them. A page load honors them. innerHTML does not. DOMParser.parseFromString does not. Anything built on either inherits that answer.

The choice is not in the template. There is nothing you can add to the response that turns it on.

One method fixes it

${html(s.fixed)}

Same request, same markup. setHTMLUnsafe() parses with declarative shadow roots allowed, and Document.parseHTMLUnsafe() does the same for a whole document. Both landed in Chrome, Safari and Firefox during 2024.

The name stops people, and it should not. Unsafe names the sanitizing, not the shadow roots. It is the same amount of unsafe as the innerHTML you already wrote.

${html(s.check)}

The version that does not depend on the swapper

You do not always own the code that swaps. htmx, Turbo and anything else holding the fetch parse the response their own way. You find out which way by testing it.

So send a fragment with no shadow root in it.

${html(s.bare)}

The element arrives as a tag and its attributes. connectedCallback finds no shadow root, attaches one and paints. That paint goes through setHTMLUnsafe, so a component nested inside this one gets its root too.

Nothing is lost by leaving it out. A declarative shadow root buys a correct first paint, and a fragment arrives long after first paint. That is why this framework strips it from a fragment and ships the element bare.

What to check today

Find every innerHTML = whose right side came from the server. Swap one piece that has a custom element in it, then read shadowRoot on that element.

If it is null, that component has been dead since the first swap, and nothing was ever going to say so.
