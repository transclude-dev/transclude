TodoMVC with no JavaScript

TodoMVC is the benchmark every framework implements: add, toggle, delete, rename, filter, mark all, clear completed. It exists to show off state management, and every version of it ships a runtime to do that.

All seven work with forms. The interesting part is not that it can be done. It is which HTML features turn out to be doing the work.

A submit button sends its own name

This is the one that makes the whole thing possible, and most people have never needed it.

${html(s.button)}

A submit button's name and value are included in the submission only when it is the button that submitted the form. Press Done and the server gets intent=toggle. Press Delete and the same form sends intent=remove.

One form, one action attribute, as many verbs as you have buttons. No routing table for them and no JavaScript deciding which one was clicked, because the browser already told you.

Seven actions, one handler

${html(s.handler)}

That is the whole of it. Read the intent, do the thing, redirect. The redirect is post/redirect/get, so a reload repeats the navigation rather than the change, and the back button does not resubmit anything.

The editing state is a URL

Renaming needs a mode: one row becomes a text field while the others stay labels. That is the piece which usually forces a client state library.

${html(s.editing)}

The row being edited is a query parameter, and the thing that sets it is a link. The server renders a text field for that row and labels for the rest. The mode survives a reload, a shared link and the back button.

Client state would not survive any of those, which is a thing nobody mentions because a click handler is quicker to write.

What it costs

A round trip per action. On a local list that is a few milliseconds and you will not see it; on a slow connection you will. That is the trade, and it is a real one rather than a free win.

What you get back is a page that works with JavaScript disabled, before the bundle loads, and while it is failing to load. There is no loading state, because there is nothing to load.

The running version ships zero bytes of JavaScript. Not a small bundle. None: view source and there is no script tag on the page.

The point is not that you should

Most applications want the round trips back. A todo list is a benchmark, not a product.

The point is which parts of the platform were sitting there unused. A submit button carries which button it was. A URL carries which row is open. Post-redirect-get handles the reload. Every one of those is older than every framework, and every one gets reimplemented in JavaScript most weeks.
