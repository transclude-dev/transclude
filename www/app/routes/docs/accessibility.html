What the defaults already do

A page sends no JavaScript. The text is on screen before any script runs. So a slow network or a blocked bundle does not stop anyone from reading it.

Navigation uses links and forms. Back, forward, find in page, open in new tab and reader mode all work, because nothing replaces them.

An element renders into the page's own DOM. So there is no boundary between a label and the input that it names, and this code works.

${html(s.label)} <label for> cannot cross a shadow boundary. An element with export const shadow = true must keep the label inside its own root. See elements for the other costs of the boundary.

What a new project starts with

npm create @transclude writes a layout. That layout already contains the parts that are hard to add to a page later.

${html(s.skip)}

The skip link is first in the document, so a keyboard user reaches it before the nav. It stays off the screen until it gets focus.

${html(s.skipCss)}

Use position: absolute, not display: none. An element hidden with display: none cannot get focus. So the link would never appear.

aria-current="page" marks the link to the page you are on. A screen reader announces that link as the current page.

The language of the page

lang in transclude.config.js sets <html lang> for every page. A screen reader uses it to choose a voice. So a wrong value is worse than no value.

${html(s.lang)}

A page in another language sets its own value. See languages.

Icons

An icon next to its own text label repeats the label. So svg-icon hides that icon from screen readers. Pass label when the icon is the only thing that says what the control does.

${html(s.icons)}

The output is different for the two icons. A labeled icon gets role="img" and an aria-label. A decorative icon gets aria-hidden="true". See icons.

Announcing a change

When a form submits, the server sends a new page. A screen reader reads the result as it reads any document. Nothing needs to announce it.

A fragment swap is different. The browser stays on the page, and only part of it changes. Put the changed text in a live element, and a screen reader reads it aloud.

${html(s.live)}

role="status" is polite, so the screen reader waits for a pause. role="alert" interrupts. So use it only when something has gone wrong.

A light element writes text and attributes into the nodes that are already in the page. It never replaces a child, so focus and selection stay where the reader put them. Your own code swaps a whole fragment. So moving focus after a swap is also your job.

Color

The generated stylesheet declares both color schemes on :root. The layout also declares them in a <meta> tag. The browser reads that tag before the CSS arrives.

Do not show meaning with color alone. The warning notes on this site have an icon as well as a border. Some readers cannot use the border, so the icon is there for them.

What you must still do

The framework renders the markup that you wrote. It adds no roles, makes up no labels and changes no order.

  • Headings in order, with one <h1> on each page.
  • A name on every control, and on every image that has meaning.
  • A visible focus style on everything that a keyboard can reach.
  • Enough contrast in both color schemes.
  • A keyboard way to do anything that a pointer can do.

A framework cannot help with the last one. A tab list or a menu has fixed keyboard rules. To build one, follow a pattern. There is no component to install.
