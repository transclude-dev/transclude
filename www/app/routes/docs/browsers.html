The minimum browser

A page of plain markup has no minimum browser. It is a document, and a browser from any year displays it.

An element with its own <style> block is the one common case that needs a recent browser. The framework wraps those styles in @scope. Browsers agreed on @scope in March 2026.

Feature What needs it In all major browsers since
@scope An element's own style block March 2026
setHTMLUnsafe() A shadow element inside swapped markup September 2025
:state() CSS that selects on a state field May 2024
Declarative shadow DOM export const shadow = true February 2024
Form-associated custom elements export const formAssociated = true March 2023

The dates come from Baseline. Each date is when the last of the major engines shipped the feature, not when the first one did.

What happens without each feature

No @scope. A browser skips an at-rule it does not know, and it skips everything inside it. So the element renders, but with none of its own styles. There is no error.

No declarative shadow DOM. The <template> stays a template, and its content never appears. A shadow element shows as an empty tag until its script defines it. Then it paints.

No :state(). The state still exists, and the element still works. Only the CSS that selects on the state does nothing.

No form association. The element renders, but its form does not include its value.

Styling an element for every browser

An element's own style block is scoped, and scoping is the new part.

${html(s.styled)}

Move the same rules into the stylesheet, and the minimum browser goes away. A light element is in the page's own DOM. So page CSS reaches it, and the tag name is the selector.

${html(s.global)}

You lose the scoping, but every browser applies the rule. If two elements each have a rule for the same selector, both rules now apply to both elements. The scope prevented that.

Features that are already optional

Speculation rules ship in one engine. speculate is off by default. A browser that does not read the block navigates in the ordinary way.

A referenceTarget ships in one engine. A browser without it ignores the attribute. Then a <label for> that names a shadow element stays unconnected, the same as with no target.

A browser that does not know Content-Security-Policy ignores the policy a page sends. The page is then no less safe than a page with no policy.

The server side

The same app runs on Node, Bun, Deno and workerd. The core imports nothing from node:. A test reads its whole import graph to keep that true. See runtimes.

No feature detection runs, and no bundle is built twice. Each of the five features above either works or does nothing. So this page is a table, not a build setting.
