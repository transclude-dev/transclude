The floor

A page of plain markup has no floor. It is a document, and a browser from any year displays it.

An element with its own <style> block is the one common thing that does. Those styles are wrapped in @scope, which browsers agreed on in March 2026.

Feature What needs it Interoperable since
@scope An element's own style block March 2026
setHTMLUnsafe() A shadow element inside swapped markup September 2025
:state() Styling on a state field May 2024
Declarative shadow DOM export const shadow = true February 2024
Form-associated custom elements export const formAssociated = true March 2023

The dates are Baseline: when the last of the major engines shipped the feature, rather than when the first one did.

What happens below each

No @scope. The browser skips an at-rule it does not know, and it skips everything inside it. So the element renders with the page's markup and none of its own styles. Nothing errors.

No declarative shadow DOM. The <template> stays a template and its content is never shown. A shadow element renders as an empty tag until its script defines it, and then it paints.

No :state(). The state is still there and the element still works. Only the CSS that selected on it does nothing.

No form association. The element renders, and its value is left out of the form it sits in.

Styling an element that has to work everywhere

An element's own style block is scoped, and scoping is the part that is new.

${html(s.styled)}

Move the same rules into the stylesheet and the floor goes away. A light element is in the page's own DOM, so page CSS reaches it, and the tag name is the selector.

${html(s.global)}

You give up the scoping and get a rule that any browser applies. For a site that has to reach old devices, that trade is worth knowing about.

Things that are already optional

Speculation rules ship in one engine. speculate is off by default, and a browser that does not read the block navigates the ordinary way.

A Content-Security-Policy is ignored by a browser that has none, which leaves that browser where it was rather than worse off.

The server side

The same app runs on Node, Bun, Deno and workerd. The core imports nothing from node:, and a test reads its whole import graph to keep that true. See runtimes.

No feature detection runs, and no bundle is built twice. Each of the five above either works or does nothing, which is why this page is a table rather than a build setting.
