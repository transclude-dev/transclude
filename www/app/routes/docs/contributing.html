Reporting a bug

Open an issue with the smallest page, element or config that shows the problem. Say which runtime you used. A .html file that shows the bug helps more than a description of the bug.

Send an email to admin@dakroub.co instead. Say what an attacker can do, and the steps you took to find it.

Running it

${html(s.setup)}

The tests need no app. npm run showcase starts the demo app, which has the browser checks. npm run www starts this site.

Before you send a change

CONTRIBUTING.md describes the layout, the test rules and the writing style. Most first pull requests miss one of these two rules from it.

Falsify before trusting. Break the code on purpose and make sure that its test fails. A test that passes both ways is not a test.

The package does not import from the apps. examples/showcase and www depend on the package by name, like any other project. A test checks this.

Code of conduct

Everyone who takes part agrees to the Code of Conduct. Be kind, talk about the work and not the person, and take new people seriously. Send reports to admin@dakroub.co. They stay private.
