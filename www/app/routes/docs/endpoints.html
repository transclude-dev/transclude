Export one handler for each verb, with an uppercase name. The verbs are GET, HEAD, POST, PUT, PATCH, DELETE and OPTIONS. A request with a verb that the file does not export gets 405. Its Allow header lists the verbs that the file exports.

Each handler returns a Response. This is the same object that the browser's own fetch gives you. Use Response.json() for most API responses.

If a handler returns nothing, or a value that is not a Response, the framework throws an error that says so. An endpoint has no template to use instead.

A whole resource

Webhooks

A webhook is an endpoint that another service calls. It is different in two ways from an API that your own pages use.

The first difference is the body. A signature covers the exact bytes that the sender sent. So verify the signature against request.text(), and parse the body after that. If you parse first and serialize again, the bytes change. Then the signature never matches.

${html(s.webhook)}

The second difference is CSRF protection. It is on by default, and it checks every method except GET and HEAD. A checked request passes if its Origin is your own site. It also passes if its content type is one that no HTML form can send.

Content type of a POST from another site Reaches your handler
application/json yes
application/x-www-form-urlencoded 403
multipart/form-data 403
text/plain, or no content type at all 403

A sender that posts JSON needs no change. Most senders post JSON.

curl -X POST /api/people sends no content type. So the guard refuses it with 403 before it reaches your handler. Add -H 'content-type: application/json' and the same request passes. This is the most common reason that an endpoint seems broken when you test it by hand. The guard refuses a sender that posts a form body. The 403 does not say why. Give the sender an origin that the guard accepts. Or limit csrf to the paths that serve your own forms.

A stream

A Response can take a ReadableStream. So an endpoint can return a stream that stays open. Server-sent events are the common use.

${html(s.stream)} When the socket closes, request.signal fires abort. When a consumer releases the reader, the stream's own cancel() runs. Unsubscribe in both places. If you do not, you leak a listener that holds a dead connection. Or you close a controller that is already closed. examples/live handles both.

Calling it from another origin

A browser on another origin gets nothing from your endpoints until you allow it. CORS is Hono middleware, and you add it in app/server.js.

${html(s.cors)}

Helpers

Every .js file in routes/ is a route. A file whose name starts with _ is not a route, so use that prefix for a helper. The same rule applies to a directory.

Put larger code outside the route tree, in app/lib/ or app/data/, and import it.

What you get by default

transclude-check checks the types of every handler. It catches a ctx field that does not exist and a handler that does not return. See types.

Every response has X-Content-Type-Options: nosniff, and that includes the response from an endpoint. An endpoint's Response goes through the same envelope as every other response. So cookies and headers are kept on a redirect.
