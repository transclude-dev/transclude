That file answers three requests.

${html(s.calls)}

One export per verb, uppercase. GET, HEAD, POST, PUT, PATCH, DELETE and OPTIONS. A verb the file does not export answers 405, with an Allow header naming the ones it does.

Each handler returns a Response, the same object the browser's own fetch gives you. Response.json() covers most of what an API returns.

Returning nothing, or anything that is not a Response, throws and says so. An endpoint has no template to fall back on.

A whole resource

The path is the route, the same as for a page. A bracketed segment is a parameter, and it arrives in ctx.params.

Reading the request

ctx.request is a standard Request. Read the body in whichever shape you need.

${html(s.body)}

A body can be read once. Take text() and parse it yourself when you need both the string and the object.

The answer

Status and headers go on the Response. ctx.cookies works here the way it does in a loader, and what it sets survives the response you return.

${html(s.response)}

Webhooks

A webhook is an endpoint somebody else calls. Two things about it differ from an API your own pages use.

The first is the body. A signature covers the exact bytes that were sent, so verify against request.text() and parse afterwards. Parsing first and re-serializing gives different bytes and a signature that never matches.

${html(s.webhook)}

The second is CSRF. It is on by default and guards every method except GET and HEAD. A guarded request passes when its Origin is your own site, or when it carries a content type no HTML form can send.

A POST from somewhere else, sending Reaches your handler
application/json yes
application/x-www-form-urlencoded 403
multipart/form-data 403
text/plain, or no content type at all 403

A sender posting JSON needs nothing, and most of them do.

curl -X POST /api/people sends no content type, so it is refused with 403 before reaching your handler. Add -H 'content-type: application/json' and the same request gets through. This is the usual reason an endpoint looks broken when it is tested by hand. A sender that posts a form body is refused, and the 403 says nothing about why. Give it an origin the guard accepts, or narrow csrf to the paths that serve your own forms.

A stream

A Response takes a ReadableStream, so an endpoint can answer with one that stays open. Server-sent events are the plain use.

${html(s.stream)} The socket closing fires abort on request.signal. A consumer letting go of the reader runs the stream's own cancel(). Unsubscribe in both, or you leak a listener holding a dead connection, or close a controller that is already closed. examples/live does both.

Calling it from another origin

Nothing is sent to a browser on another origin unless you say so. CORS is Hono middleware in app/server.js.

${html(s.cors)}

Helpers

Every .js file in routes/ is a route. Give a helper a _ prefix and it is not one. The same goes for a directory.

Anything larger belongs outside the route tree, in app/lib/ or app/data/, and is imported.

What you get for free

transclude-check types every handler, so a ctx field that does not exist and a handler that forgets to return are both caught. See types.

X-Content-Type-Options: nosniff is on every response, an endpoint's included. Its Response goes through the same envelope as everything else, so cookies and headers survive a redirect.
