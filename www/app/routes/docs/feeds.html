Sitemap

Set a hostname, and the app serves /sitemap.xml. The sitemap lists every page route with no parameters. A route with parameters is listed as the URLs that its paths() export names. The build prerenders the same list.

${html(s.sitemap)}

A route with no paths() is left out, because the pattern itself is not a URL. Add any other URLs in entries, as an array or a function. exclude takes a path or a pattern. Each one is tested against the encoded path that the sitemap writes. So /p/a b and /p/a%20b leave out the same URL. A pattern finds é as %C3%A9. A path begins with /. Any other value in exclude fails the build.

${html(s.sitemapEntries)}

An entry may name a URL that a route already produced. The sitemap then lists that URL once, with the fields of both. That is how a page built from paths() gets a lastmod. The two are compared encoded, so /p/a%20b names the URL of /p/a b.

An entry may also have lastmod, changefreq and priority. A lastmod is a date, a number of milliseconds, or a string that a date can parse. It is written as the day in UTC. A value that is not a date is left out. A changefreq is one of always, hourly, daily, weekly, monthly, yearly and never. A priority is a number from 0 to 1. Any other value in those two fails the build.

The hostname is an origin, like https://acme.com, with no path and no user or password. An entry's path begins with /. Every URL is joined to the hostname, so any other value fails the build.

Above 50,000 URLs, /sitemap.xml becomes an index. Each part of the list is then a separate file: /sitemap-0.xml, /sitemap-1.xml and so on. The build writes every one, so a static host serves the same files. To see this on a small site, lower limit.

Feeds

A sitemap comes from the route table, because it lists only URLs. A feed needs a title, a date and something to read. So you pass in the items.

${html(s.feed)}

That serves /feed.xml as RSS 2.0. Each item needs a title and a path. An item without one of them fails the build. date, description, content and author are optional. Put full HTML in content.

Items are published newest first, with a maximum of 50. Set limit for a different number.

Atom

format: 'atom' writes Atom 1.0 instead. The spec requires an author and a date. So the feed needs an author, or every item needs its own. At least one item needs a date.

${html(s.atom)} Nothing here reads the clock. The feed gets its date from its newest item. So a build that changes nothing writes the same bytes. If the items have no dates, set updated on the feed.

Telling a feed reader where the feed is

A feed reader looks for a <link> in the page. This framework does not write one. The config contains the title, but you decide which pages show the feed. Put the link in the layout above the pages that the feed covers.

${html(s.discovery)}

Where the files go

The app serves both files, and the build writes both into dist/static. A host that serves that directory has them without running any code.
