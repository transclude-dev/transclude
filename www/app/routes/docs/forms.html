One export per method

Each handler has the name of its HTTP method, in uppercase. Endpoints use the same names, so you learn one spelling.

${html(s.verbs)}

A <form> can send only GET or POST. HTML sets this limit, not this framework. To delete something from a form, post a hidden field that says so. Then POST reads it.

${html(s.intent)}

From a script, you can send the method directly, and DELETE runs.

${html(s.fetch)}

Answer a change with a redirect

Use a 303. The browser then loads the new URL with a GET, so a reload does not submit the form again. Two cases skip the redirect. A rejected submission changed nothing. A fragment request asked for markup.

${html(s.redirect)}

Every handler returns the same fields

ctx.action contains the value the handler returned. Its type is a union of the return types of every handler. If only one handler sets a field, the others do not have it. So reading that field in the loader is a type error.

Give every handler the same fields. Set the fields that do not apply to null.

A response body can be read only one time. A module-level const badRequest = new Response(…) works for the first request. Every later request gets a 500, because the body was already read.

CSRF

CSRF protection is on by default. It covers non-GET requests that have a form content type. Set csrf: false to turn it off, or pass an object to allow another origin.
