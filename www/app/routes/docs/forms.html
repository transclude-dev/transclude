One export per method

Handlers are named for their HTTP method, in uppercase. Endpoints are written the same way, so there is one spelling to learn.

${html(s.verbs)}

A <form> can only send GET or POST. That is HTML, not a limit here. To delete something from a form, post a hidden field saying so and let POST read it.

${html(s.intent)}

From script you can send the method directly, and DELETE runs.

${html(s.fetch)}

Answer a mutation with a redirect

Use a 303, so the URL the browser lands on is a GET and a reload does not submit again. Two things skip it: a rejected submission, which changed nothing, and a fragment request, which asked for markup.

${html(s.redirect)}

Every handler returns the same fields

ctx.action holds whatever the handler returned, and its type is every handler's return type at once. A field that only one of them sets is missing from the others, so reading it in the loader is a type error.

Give every handler the same fields and leave the ones that do not apply as null.

A body can be read once. A module-level const badRequest = new Response(…) works for the first request and comes back empty after that.

CSRF

On by default, covering non-GET requests that have a form content type. Set csrf: false to turn it off, or pass an object to allow another origin.
