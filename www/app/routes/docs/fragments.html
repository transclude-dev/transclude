Use one for anything that changes while the rest of the page stays put. Search results as you type. A list after something is added to it. The next page of a table. Fetch the region and replace the copy in the page, instead of loading the whole document again.

Mark a region

Give the element an id and a fragment attribute.

${html(s.page)}

That page answers three URLs.

Request Response
GET /?q=ada the whole document
GET /?q=ada&fragment=matches the <ul> and nothing else
GET /?fragment=nope 404

The second one returns this:

${html(s.response)}

The id is the name. The URL asks for matches, and a swap targets #matches. The page and the fragment come from one template, so the two always agree.

Ask for one

A fragment is an ordinary URL. Anything that fetches HTML can use it.

${html(s.fetch)} setHTMLUnsafe() builds shadow roots from the markup it is given. A shadow element arriving in a fragment needs it to start up.

htmx does the same with attributes. Turbo and htmz are other options. This framework ships none of them, and nothing here depends on one.

${html(s.htmx)}

htmx sends the target's id in an HX-Target header. Name that header in the config and ?fragment= becomes optional.

${html(s.header)}

Strict parameter, loose header

?fragment=nope is a 404. Someone wrote that name into a URL, so getting it wrong says so.

A header naming a fragment is a hint, and an unknown name is ignored. Client libraries send these headers on every request, including ones that want a whole document. HX-Target from htmx works this way. Naming a header in fragmentHeader adds it to Vary.

Actions

POST /?fragment=nope changes nothing and returns 404. The region is checked before the action runs.

ctx.fragment tells a form submission from a fetch. The first wants a redirect, the second wants markup.

Styles for swapped-in markup

A fragment can land on a page that never rendered the elements inside it. Those elements have no definition there and no styles. Set watchElements in the config. Every page then carries a small script that notices a new tag, loads its definition and adds its styles once.

It is off by default. It puts that script on every page, and it earns its place only when swaps bring in elements the page did not already render. This site leaves it off.
