Use a fragment for any part that changes while the rest of the page stays the same. Examples are search results as you type, a list after you add an item, and the next page of a table. Fetch the fragment and replace the old copy in the page. You do not load the whole document again.

Mark a fragment

Give the element an id and a fragment attribute.

That page answers three URLs.

Request Response
GET /?q=ada the whole document
GET /?q=ada&fragment=matches the <ul> and nothing else
GET /?fragment=nope 404

The second one returns this:

${html(s.response)}

The id is the fragment's name. The URL asks for matches, and a swap targets #matches. The page and the fragment come from one template, so the two always agree.

The loader reads the URL, so the page has prerender = false. Without it, the build writes the page to one file, and every ?q= gets that file. See production.

Ask for one

A fragment has an ordinary URL. Any tool that fetches HTML can use it.

A browser never sends the URL fragment to a server. It keeps everything after the # for itself. So GET /notes#list arrives as GET /notes. The server cannot know that you wanted a part. A query parameter is sent with the request, so the parameter does the asking.

The # form does appear in this framework, in <transclude src="/notes#list">. The server resolves it while it renders the page. At that point it has the whole URL, and nothing is sent anywhere. <use href="/icons.svg#check"> works for a similar reason. The browser fetches the whole file, then finds the part. A fragment exists so that you do not download the whole document. So the request must name the part it wants.

${html(s.fetch)} setHTMLUnsafe() builds a declarative shadow root from its markup. innerHTML does not. A shadow element arrives in a fragment with no shadow root, and it renders itself when it connects. So either method starts it. A fragment that contains a declarative root needs setHTMLUnsafe(). That root can be written by hand, or an include can bring it in.

htmx does the same with attributes. Turbo and htmz are other options.

${html(s.htmx)}

htmx sends the target's id in an HX-Target header. If you name that header in the config, ?fragment= becomes optional.

A fragment arrives with its own id. By default, htmx fills the target instead of replacing it. So the returned <ul id="list"> goes inside the one already on the page. The next request puts another one inside again. ${html(s.header)}

Strict parameter, loose header

?fragment=nope is a 404. A person wrote that name into a URL, so a wrong name gets an error.

A header that names a fragment is only a hint. The server ignores an unknown name. Client libraries send these headers on every request, including requests for a whole document. HX-Target from htmx works this way. When you name a header in fragmentHeader, the server adds it to Vary.

Caches and the parameter

A fragment is a different body at the same path, so a cache must keep the two apart. A cache does this without help, because the query string is part of its key.

A response can remove that separation with No-Vary-Search. This header tells a cache which parameters do not change the response. A campaign tag does not change it, but fragment does. Name each parameter that a cache can ignore.

${html(s.novary)} except=() is the short way to write "ignore every parameter". With it, a cache could answer ?fragment=list with the whole document. A swap would then write the whole page into the element it should replace. The server reads this header on each response. It throws an error that names the value it read. It reads a name the same way a cache does, so fr%61gment is fragment. The server also refuses a value with params or except in a form it cannot read.

Actions

POST /?fragment=nope changes nothing and returns 404. The server checks the fragment before the action runs.

Use ctx.fragment to tell a form submission from a fetch. A form submission wants a redirect. A fetch wants markup.

Styles for swapped-in markup

A fragment can arrive on a page that never rendered the elements inside it. On that page, those elements have no definition and no styles. Set watchElements in the config. Then every page gets a small script. The script finds each new tag, loads its definition and adds its styles once.

It is off by default, because it puts that script on every page. Turn it on only when swaps bring in elements that the page did not already render. This site leaves it off.

Includes put a fragment in a second place on the server.
