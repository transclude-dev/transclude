The file

app/routes/notes.html handles /notes. It contains the markup and the code that loads its data.

What it compiles to

The file compiles to one module with a fixed set of exports. Each later stage reads one of these exports. Below is the real output for the file above. The build compiled it when it built this page.

${html(module)}
Export Comes from

The fragment is the same markup

The compiler makes regions.list from the <ul>. It does this in the same pass that makes render. Nine lines are the same in both, character for character.

${html(regions)} Fragments explains the URL. GET /notes?fragment=list calls this function instead of render. It passes the data that the same loader returned.

What the build decides

The build runs each loader once. If a page reads nothing about the request, the build renders it to a file. Some pages read a cookie, set a header or return a Response. Such a page cannot be one file for every visitor. The build names that page and says which of those things it did. Then the build exits with a non-zero code.

What handles a request

Every step before the route runs for every request. This includes a request that ends at a file. The order is fixed.

Step What it does
1 Trailing slash /notes/ redirects to /notes with a 301.
2 CSRF A form post from another origin is refused with a 403.
3 nosniff On every response, including a public file.
4 Your middleware app/server.js, before any step that sends bytes.
5 Public files A real file wins over a [...path] catch-all.
6 The route The router matches the directory tree.

Inside the route, in this order:

  1. The layout chain, outermost first. Any layout can return a Response and stop every step below it.
  2. The action, for a request that is not GET. The fragment name is checked before this step.
  3. The page loader.
  4. render for a document, regions[name] for a fragment.
  5. Includes, the head, and the policy built from the page's inline scripts.

The same module, used in four ways

Request What runs
GET /notes load, then render. The whole document.
GET /notes?fragment=list load, then regions.list. The <ul> and nothing else.
POST /notes POST, then the loader and render again.
<transclude src="/notes#list"> load, then regions.list, inside another page. See includes.
The loader runs again after the action. So the page renders the result of the action. A request that changes something runs the loader twice, and this is on purpose.

What the browser gets

The client export above is empty, so this page sends no JavaScript. A page sends JavaScript only when it renders an element with behavior. Then it sends JavaScript only for those elements. The <script server> block is compiled into the route, and it never appears in the page.

The explorer follows this file through the same steps. It shows the module behind every stage, and each stage has its own page. src/document.js is a URL, so you can link to a line in the compiler.
