The build compiles the directory into /icons.svg, one document of <symbol>s. Point a <use> at a symbol by its file name:

${html(s.use)}

That is all there is to the feature. One request serves every icon in the library. The browser caches it, so the second page costs nothing.

Libraries

A subdirectory of app/icons/ is a separate library, served under its name. A downloaded icon set is a folder of SVG files. So put the folder here, and refer to an icon by library and name.

${html(s.library)}

Files at the top level are the icons library. So the server sends them at /icons.svg. Two libraries can each have a check. They are different files in different sheets, so you do not rename either one.

A sheet sends every icon in it

A library is one file. So a page that draws one icon downloads all of them. A sprite makes this trade: one request, cached one time, however many icons the page shows.

The trade stops being good at a few hundred icons. A 24-pixel line icon is about 150 to 300 bytes in the sheet. A set of 1,500 is a few hundred kilobytes. Every visitor downloads all of it to draw twelve icons.

So copy only the icons you use, not the whole set. A downloaded folder is a good way to start but a bad way to ship. If you move a file out of it later, only the library name in the URL changes.

The build writes every file it finds. It cannot tell which icons a page draws. A name can be an expression, and a server-rendered route is never prerendered. Markup can also come from a loader. A sheet contains exactly the files you put in the directory.

What the build writes

check.svg becomes #check. The build reports the icon count next to the pages it prerendered.

${html(s.sprite)}

The build keeps viewBox and every paint setting in the file. It removes width and height, because they would conflict with the CSS that sizes the icon.

Icons that several apps share

iconsDir can list several directories. So the build reads a package of shared icons together with the app's own icons. Each entry is a path from appDir, and a path can go outside it.

${html(s.shared)}

All libraries with the same name become one sheet. The app's lucide/ and the package's lucide/ are both /lucide.svg. To add an icon to a shared set, an app puts the icon in its own directory. Each icon comes from one file. If two of the directories contain the same icon, the build stops and names both files. It does not silently pick one.

A symbol scales by its viewBox. The build refuses a file without one, and names the file. Otherwise the icon would render at the wrong size, and it would look like a CSS problem. The build refuses app/icons/lucide/arrows/up.svg. If it flattened the path, two files could get the same id. If it skipped the file, an icon would go missing with no message. Move the directory up, so it becomes a separate library. An icon next to its own label repeats the label. So the element hides the icon from a screen reader. Pass label when the icon is the only content, as in a button with no text. app/icons/lucide/ serves /lucide.svg. A file at app/public/lucide.svg would use the same URL. The build and the dev server do not pick one. Both stop until you rename one of the two. This does not affect other public files. <use> draws the symbol in a separate tree. So page CSS applies to the whole icon, not to one path inside it. If an icon needs two colors that you control, paste its SVG into the markup by hand. <use href> is also same-origin. So this app must serve the sprite, not a CDN.
