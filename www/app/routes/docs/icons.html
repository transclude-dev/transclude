app/icons/ holds one SVG file per icon. Each is a whole SVG document you can open, edit and diff.

${html(s.dir)}

The build compiles the directory into /icons.svg, one document of <symbol>s. Point a <use> at one by file name:

${html(s.use)}

That is the whole feature. One request serves every icon on the site, the browser caches it, and the second page costs nothing.

What the build writes

check.svg becomes #check. The build reports the count beside the pages it prerendered.

${html(s.sprite)}

viewBox is carried over, and so is everything the file says about paint. width and height are dropped, because they would fight whatever CSS sizes the icon.

An element for it

<use> works on its own. Most sites want a name instead of a URL, which is six lines in app/elements/:

${html(s.element)} ${html(s.usage)}

Light DOM, so no JavaScript is shipped and the page's own CSS reaches inside. GET / returns the icon already drawn:

${html(s.output)}

Size and color

The element above sizes an icon at 1em, so it matches the text beside it. Most icon sets draw with stroke="currentColor", which takes the color of the text too. Both follow from the surrounding rule:

${html(s.color)}

Configuration

iconsDir names the directory, relative to appDir. Set it to null for no icons.

${html(s.config)} A symbol scales by its viewBox. A file without one is refused by name rather than built. The icon would otherwise render at some other size and read as a CSS problem. Subdirectories are read, and an icon is still named by its file alone, so ui/check.svg and nav/check.svg ask for the same #check. The build names both and stops. An icon beside its own label repeats it, so the element hides it from a screen reader. Pass label when the icon is the only thing there, as in a button with no text. A file you write at app/public/icons.svg asks for the same URL as the sprite. Rather than pick a winner, the build and the dev server both stop until one of them is renamed. <use> draws the symbol in a tree of its own, so page CSS reaches the whole icon and not one path inside it. An icon that needs two colors under your control is one to paste into the markup by hand. <use href> is also same-origin, so the sprite is served by this app rather than a CDN.
