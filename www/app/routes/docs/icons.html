app/icons/ holds one SVG file per icon. Each is a whole SVG document you can open, edit and diff.

${html(s.dir)}

The build compiles the directory into /icons.svg, one document of <symbol>s. Point a <use> at one by file name:

${html(s.use)}

That is the whole feature. One request serves every icon in the library, the browser caches it, and the second page costs nothing.

Libraries

A subdirectory of app/icons/ is a library of its own, served under its name. An icon set you downloaded is a folder of SVG files, so put the folder here and reference it by library and name.

${html(s.library)}

Files loose at the top are the icons library, which is why they are served at /icons.svg. Two libraries may each have a check: they are different files in different sheets, and neither has to be renamed.

What the build writes

check.svg becomes #check. The build reports the count beside the pages it prerendered.

${html(s.sprite)}

viewBox is carried over, and so is everything the file says about paint. width and height are dropped, because they would fight whatever CSS sizes the icon.

An element for it

A new project already has this file. <use> works on its own, and most sites want a name instead of a URL. npm create @transclude writes app/elements/svg-icon.html and leaves it to you. Nothing in the framework defines it, so change the sizing, add a class, or delete it.

Size and color

The element above sizes an icon at 1em, so it matches the text beside it. Most icon sets draw with stroke="currentColor", which takes the color of the text too. Both follow from the surrounding rule:

Configuration

iconsDir names the directory, relative to appDir. Set it to null for no icons.

${html(s.config)} A symbol scales by its viewBox. A file without one is refused by name rather than built. The icon would otherwise render at some other size and read as a CSS problem. app/icons/lucide/arrows/up.svg is refused. Flattening it would give two files one id, and skipping it would lose an icon without saying so. Move the directory up to be a library of its own. An icon beside its own label repeats it, so the element hides it from a screen reader. Pass label when the icon is the only thing there, as in a button with no text. app/icons/lucide/ answers for /lucide.svg, so a file you write at app/public/lucide.svg asks for the same URL. Rather than pick a winner, the build and the dev server both stop until one of them is renamed. Public files you have not named after a library are served as they always were. <use> draws the symbol in a tree of its own, so page CSS reaches the whole icon and not one path inside it. An icon that needs two colors under your control is one to paste into the markup by hand. <use href> is also same-origin, so the sprite is served by this app rather than a CDN.
