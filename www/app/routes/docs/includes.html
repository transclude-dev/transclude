A fragment of this page

The fragment is already a function of the page's data, so including it is a call. One copy of the markup, in two places.

A fragment of another route

${html(s.route)}

That route's loaders run and its layouts' markup does not, the same as when a fragment is asked for over HTTP. It is rendered in this process, not fetched. One route included twice runs its loaders once.

A page that includes a route reading a cookie is personal too. The cache will not hold it, and the build will not write it to a file.

A document somebody else wrote

${html(s.site)}

The only form that leaves the server, and the only one that needs configuring. A page you did not write marks no fragments, so which piece to take is worked out from its HTML. That is the second half of this page.

Children are the fallback

On success they are dropped. If the source cannot be read they render in its place. With no children, a source that fails stops the render.

That covers a source being down. A source nobody allowed, or an include that goes round in a circle, throws instead: those are mistakes to fix.

Resolved before the page renders

The compiler collects what a page includes, and the server has the answers ready before it renders.

That is what keeps a page a file: a prerendered page reads its sources once, at build time, and carries the result.

Reading a document that marks nothing

Your own pages say what a fragment is. A page somebody else wrote does not. The rest of this is how a piece of one is found and made safe to show.

This copies. Your server reads the document and serves the piece from your origin, as part of your page. A prerendered page carries it in a file that ships with your build. Name a host only when you have the right to republish what it holds. Read its license and its terms first: a share-alike license can put conditions on the page you put the fragment in.

Nothing is attributed for you. Write the credit yourself, next to the include.

How extent is worked out

An id says what a thing is, not where it ends. Only what HTML already encodes is used:

  • A heading takes everything after it up to the next heading of its own rank or above. An h2 absorbs its h3s; an h3 stops at the next h3 or any h2. A run never crosses out of its parent.
  • A <dt> takes its definitions up to the next term.
  • Everything else is returned as itself, with no inference at all.

An empty inline element is a bookmark for what follows it, which is how anchors are written in older documents. This resolves the heading and its section.

${html(s.bookmark)}

One hop only. An element holding text or an image is content.

Documents with no ids

A heading with no id gets one from its text, lowercased, punctuation removed, spaces hyphenated. Letters keep their own script rather than folding to ASCII.

Explicit ids win, and the whole table is worked out before anything is resolved, so a name means the same thing on every request. An id further down the page beats a heading further up, and the heading takes the next name.

A heading run is several siblings, not one element. It arrives as it appears in the source, so it matches the page it came from.

What arrives

Scripts, frames, plugins and event handlers are removed. javascript: URLs are dropped everywhere; data: survives only on an image source. <base>, <link> and <style> go too, because none of them stop at the fragment. A <base> retargets every relative URL in the page the fragment lands in. The other two restyle that whole page: one pulls a stylesheet from anywhere, and one carries it.

A style attribute is kept, because it paints the element it sits on and nothing else. A highlighted code block carries its colors that way. Set styles: 'strip' to drop them and leave the look to your own CSS.

Every relative URL is made absolute against the source, including a hash-only href, which otherwise addresses an id in your page. srcset is parsed, since a candidate URL may contain a comma, and url() is rewritten inside a style attribute.

A custom element from the source arrives with no definition behind it. It is inert, so a section built out of them will look empty.

Limits

${html(s.tuning)}

Redirects are followed one at a time, and every hop is checked again. The check that passed on the URL you configured says nothing about where the third redirect landed. Addresses on the private ranges are refused, including the cloud metadata endpoint and IPv4 addresses written in IPv6 form.

maxAge is how long a document already read is used without asking the source again, so several fragments of one page cost one read. After that it is revalidated with ETag and Last-Modified.

On Node and Deno a hostname is resolved and every address it answers with is checked. workerd has no resolver, so there that check does not run and the allowlist is the whole defense. Name hosts you trust, and treat a wildcard as trust in everything under it.

The endpoint

Naming a host also mounts /_transclude/proxy. Ask it for a fragment of an allowed document from anywhere.

${html(s.request)}

With no id, the answer is the document's outline, and what the cleaning removed.

${html(s.outline)}

It answers with the fragment, sanitized and rewritten. It is same-origin, which the default policy requires. That policy names 'self' and refuses a cross-origin fetch.
