Overview

An HTML-first server framework. A page is one file, and the directory tree is the route table.

A page contains two parts. A <script server> block loads the data, and the markup shows it. The server runs both parts and sends the result.

${html(s.page)}

The browser gets finished HTML. No client framework starts up. No second request fetches the data. No code has to run before the page works.

Your folder structure sets your routes. A page responds to GET. Its loader receives the URL, the path parameters and the cookies. To handle a form, export POST from the same file. A .js file next to the page becomes an API endpoint. The server runs on Hono.

The framework is HTML-first and hypermedia-driven. The markup from the server is the state of your app. Links and forms change that state. If this idea is new to you, Hypermedia Systems is a good place to start.

This site uses transclude. Each page you read here is one .html file in www/app/routes/.

Everything in one file

Data loading, markup, styles and behavior are in one file. The URL points to that file.

Fetch any part of a page

Mark an element as a fragment, and you can request only that element. The same compiled markup serves it.

Light DOM by default

An element renders into the DOM of your page. Your page CSS applies to it. An element without behavior ships no JavaScript. Add a shadow root only when you want one.

Runs anywhere

Node, Bun, Deno and workerd, from the same code.

Where the name comes from

Ted Nelson created the word hypertext in the 1960s. The web is built on hypertext: you click a link and get a new document. Transclusion is the other half of the same design, but the web did not adopt it. Transclusion puts part of one document inside another. It points to the part and does not copy it. So one piece of writing can be in two places and still be one piece. Nelson described it in Literary Machines, his book about Project Xanadu.

HTML can include a whole resource by pointing to it. Examples are an image, a stylesheet, a script, or another page in an <iframe>. But HTML has no way to take one part of a document and put it in another. An iframe is a separate document in a box, with its own styles and layout. Its content never becomes part of your text.

SVG is the only part of the platform that does this. <use href="#icon"> points to an element by its id and renders it in place. That is transclusion, and browsers support it. But it works for shapes, not paragraphs.

transclude does this in two ways. An element is markup that the server puts into the page that uses it. A fragment is a part of a page that has its own URL. You can render it in place or fetch it on its own. In both cases, there is one copy of the markup.
