Overview

An HTML-first server framework. A page is one file, and the directory tree is the route table.

A page holds both halves: a <script server> block that loads its data, and the markup that reads it. The server runs them together and sends the result.

${html(s.page)}

What reaches the browser is finished HTML. No client framework starts up, no second request fetches the data, and nothing has to run before the page works.

Your folder structure is your routing. A page responds to GET, and its loader receives the URL, the path parameters and the cookies. Export POST from the same file to handle a form. Put a .js file beside it and it becomes an API endpoint. Hono runs the server.

It is HTML-first and hypermedia-driven. The markup the server sends is the state of your app, and links and forms change it. If that idea is new to you, Hypermedia Systems is a good place to start.

This site is built with it. Every page you are reading is one .html file in www/app/routes/.

Everything in one file

Data loading, markup, styles and behavior live together in the file the URL points at.

Fetch any part of a page

Mark an element and you can request just that piece, from the same compiled markup.

Light DOM by default

An element renders into your page's own DOM. Your CSS reaches it, and one without behavior ships no JavaScript. Opt in to a shadow root when you want one.

Runs anywhere

Node, Bun, Deno and workerd, from the same code.

Where the name comes from

Ted Nelson coined the word hypertext in the 1960s, and the web was built on it: a link, a click, a new document. Transclusion is the other half of the same design, and the web left it behind. It means putting part of one document inside another by pointing at it rather than copying it. A piece of writing can sit in two places and still be one piece of writing. Nelson set it out in Literary Machines, the book describing his Project Xanadu.

HTML has always pulled in a whole resource by pointing at it: an image, a stylesheet, a script, another page in an <iframe>. What it has never had is a way to take one part of a document and make it part of another. An iframe is a separate document in a box, with its own styles and its own layout. It never becomes your text.

SVG is the one place the platform does this. <use href="#icon"> points at an element by id and renders it in place, which is transclusion, shipped and working. It does shapes, not paragraphs.

transclude does that two ways. An element is markup pulled into the page that calls it. A fragment is a piece of a page that keeps a URL of its own. Render it in place, or fetch it by itself. Either way there is one copy of the markup.
