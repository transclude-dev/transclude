The language of every page

lang is what lands on <html>.

${html(s.config)}

It defaults to en. That default is a guess about your app, so a generated project writes the key out where you can see it and change it.

A screen reader picks a voice from this, and a browser picks a dictionary and a set of quotation marks. A wrong value is worse than a missing one.

One page in another language

A page sets its own attributes with a bare <html> tag. It is merged into the document rather than rendered, and it wins over the config.

${html(s.page)}

Direction rides along with it.

${html(s.rtl)} padding-inline-start flips with the text. padding-left does not, so a right-to-left page gets its gutter on the wrong side. The same holds for margin, border and text-align. ${html(s.logical)}

A locale in the URL

A locale is a route parameter. The directory tree is already the route table, so nothing new is needed to give each language its own URL.

${html(tree)}

/cy/about and /en/about reach the same file, and the loader reads which one was asked for.

${html(s.loader)}

Your strings are a module the loader imports.

${html(s.copy)}

GET /cy/about returns a Welsh page with <html lang="cy">. Both URLs are in the sitemap, and the build prerenders both.

Sending a reader to their own language

Accept-Language is a request header, so reading it is middleware. Redirect from the bare path and let each locale keep its own URL.

${html(s.negotiate)} Serving different languages at one URL needs Vary, and a cache that ignores it hands one reader another reader's language. A redirect to a URL per locale is one page per URL, which is what every cache and every link already understands.

What this framework does not ship

There is no message catalog, no plural rule engine and no locale negotiation beyond what you write above.

This is the same answer cache and markdown get. Which catalog format, which fallback chain and which plural library are decisions about your app. A framework that picked one would be picking for every app.

The platform ships most of it. Intl formats dates, numbers, lists and plurals, and it runs on all four runtimes. A loader calls it and the page gets text.
