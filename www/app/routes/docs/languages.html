The language of every page

The lang key sets the lang attribute on <html>.

${html(s.config)}

The default is en. That default is a guess about your app. So a generated project writes the key in the config, where you can see it and change it.

A screen reader uses this value to choose a voice. A browser uses it to choose a dictionary and a style of quotation marks. A wrong value is worse than no value.

One page in another language

A page sets its own attributes with a self-closing <html> tag. The renderer does not print this tag. It merges the attributes into the document, and they win over the config.

${html(s.page)}

Set the text direction in the same tag.

${html(s.rtl)} padding-inline-start changes sides with the text direction. padding-left does not. So a right-to-left page gets its gutter on the wrong side. The same is true for margin, border and text-align. ${html(s.logical)}

A locale in the URL

A locale is a route parameter. The directory tree is already the route table. So each language gets its own URL with no new feature.

${html(tree)}

/cy/about and /en/about go to the same file. The loader reads which locale the request asked for.

${html(s.loader)}

Put your strings in a module that the loader imports.

${html(s.copy)}

GET /cy/about returns a Welsh page with <html lang="cy">. Both URLs are in the sitemap, and the build prerenders both.

Sending a reader to their own language

Accept-Language is a request header, so read it in middleware. Redirect from /, and let each locale keep its own URL.

${html(s.negotiate)} If you serve different languages at one URL, you need a Vary header. A cache that ignores it can give one reader another reader's language. A redirect gives each locale its own URL, so each URL has one page. Every cache and every link already works with that.

What this framework does not include

There is no message catalog and no plural rule engine. There is no locale negotiation other than the code that you write, as above.

The cache and markdown config keys follow the same rule. The catalog format, the fallback chain and the plural library are decisions about your app. If a framework picked one, it would pick for every app.

The platform already includes most of it. Intl formats dates, numbers, lists and plurals. It runs on all four runtimes. A loader calls it, and the page gets the formatted text.
