${html(s.layout)}

The page renders into the <slot>. To have more than one slot, give a slot a name.

${html(s.named)}

Nesting

A _layout.html in a subdirectory renders inside the layout above it. Put a nav in the root layout and a sidebar in the section layout. A page in that section then gets both.

${html(nested)}

Each layout loads its own data. Each layout also has its own <slot>, and the layout or page below it fills that slot. A loader can also read the data that the layouts above it returned, as ctx.layout.

A layout can respond on its own

If a layout loader returns a Response, the request stops there. Nothing below it runs. So you write a login redirect only once.

${html(s.guard)}

Actions are also below the layout. A POST to a page under this layout runs the guard first. So a signed-out request never gets to the handler. After the action, the render runs the layout loaders again. So each loader runs twice on a request that changes something. This is on purpose. The page shows the data after the action, not the data from before it.

Give the page export const prerender = false. A guard reads a cookie. A page that reads a cookie has a different answer for each visitor, so the build refuses to write it to a file. The build names the page, says why, and exits non-zero. It does not ship a signed-out copy.

Middleware in app/server.js does not run during the build. So middleware cannot replace a guard in a layout.

Attributes on <html> and <body>

The root layout controls the document. So set a theme or a text direction there. If you write <html> in a layout, its attributes go on the document's <html>. A <title> anywhere in the chain works the same way. It becomes the document's title.

${html(s.htmlAttrs)}

The attributes merge by name along the chain, and the innermost level wins. So a root layout can set the theme, and a page can set dir. Values are escaped. An attribute with no value is true. A value of false or null removes the attribute. lang is set already, and you can overwrite it.

<body> works the same way. Put a class there when the page's CSS uses it.

${html(s.bodyAttrs)} Many levels can write <html> or <body>, but the document gets only one of each. The server collects the attributes from every level and writes them once. If a tag had two class attributes, the parser would use the first one. That is the outermost one, which is the wrong one.

Sharing the response

Every loader in the chain gets the same ctx.response. So if a layout sets a status, the server sends that status.
