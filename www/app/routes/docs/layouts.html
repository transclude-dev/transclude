${html(s.layout)}

The page renders into <slot>. Name a slot to offer more than one.

${html(s.named)}

Nesting

A _layout.html in a subdirectory renders inside the one above it. Put a nav in the root layout and a sidebar in the section layout, and a page in that section gets both.

${html(nested)}

Each one loads its own data, and each gets its own <slot> filled by whatever is below it. A loader also reads what the chain above it returned, as ctx.layout.

A layout can respond on its own

Return a Response from a layout loader and it stops there. Nothing below it runs, which is how you write a login redirect once.

${html(s.guard)}

The actions are below it too. A POST to a page under this layout runs the guard first, so a signed-out request never reaches the handler. The render that follows asks the layouts again, so each loader runs twice on a request that changes something. That is on purpose: the page renders from what the action just did, not from what was true before it.

Give it export const prerender = false. A guard reads a cookie, and a page that reads one has an answer per visitor, so the build refuses to write it. It names the page, says why, and exits non-zero, rather than shipping a signed-out copy.

Middleware in app/server.js does not run during the build. Nothing there can stand in for a guard in a layout.

Attributes on <html> and <body>

The root layout owns the document, so it is where a theme or a text direction belongs. Write <html> and its attributes become the document's, the same way a <title> anywhere in the chain becomes the document's title.

${html(s.htmlAttrs)}

They merge by name along the chain, innermost winning, so a root layout can set the theme and a page can set dir. Values are escaped, a bare attribute is true, and false or null drops it. lang is there already and can be overwritten.

<body> works the same way, and is where a class the page styles itself with belongs.

${html(s.bodyAttrs)} You write one <html> or <body> and the document gets one. The attributes are collected from every level and serialized once. Two class attributes in a tag would leave the parser taking the first, which is the outermost, which is backwards.

Sharing the response

Every loader in the chain holds the same ctx.response, so a layout that sets a status sets the one the server sends.
