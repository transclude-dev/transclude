The order

  1. Trailing-slash redirect
  2. CSRF
  3. app/server.js
  4. Public files
  5. Routes

app/server.js runs before anything that serves bytes, so a guard covers prerendered pages and public files. Public files come before the route table, so a real file beats a [...path] catch-all.

Paths that are not public

Middleware does not run during the build. So nothing there can tell a gated page from an open one. A page behind a guard is written to a file in its signed-out state, and any static host then serves it.

gated is how the build finds out. It writes no file for those paths and leaves them out of the sitemap. They are still routes, and the middleware still answers them at runtime.

${html(s.gated)}

A path matches itself. /api/* matches that path and everything under it. An entry that is not a path fails the build. So does one that covers no route, URL or public file. A misspelled path would otherwise fail open, with the file written and the build reporting a success.

The build runs layout loaders, and a guard reads a cookie, which the build refuses to write down. Nothing runs app/server.js during a build, which is why this one has to be declared.

Trailing slashes

trailingSlash sets the router mode and the redirect together.

Value Result
'never' One URL per page. /about/ redirects with a 301.
'ignore' Both URLs return 200.

'ignore' leaves one page reachable at two URLs, so say which one counts: canonical: true in the config writes <link rel="canonical"> on every page. The loose router hands the path over with the trailing slash already gone, so the tag names the same URL either way.
