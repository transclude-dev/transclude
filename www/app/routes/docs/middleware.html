The order

  1. Trailing-slash redirect
  2. CSRF
  3. app/server.js
  4. Public files
  5. Routes

app/server.js runs before any step that sends bytes. So a guard in it also protects prerendered pages and public files. Public files come before the routes. So a real file wins over a [...path] catch-all route.

Paths that are not public

Middleware does not run during the build. So the build cannot tell a gated page from an open page. The build writes a guarded page to a file as a signed-out visitor sees it. Then any static host serves that file.

The gated export tells the build which paths are guarded. The build writes no file for those paths, and it leaves them out of the sitemap. They are still routes, and the middleware still handles them at runtime.

${html(s.gated)}

A path matches only itself. /api/* matches /api and every path under it. An entry that is not a path stops the build with an error. An entry that matches no route, URL or public file also stops the build. Without this check, a misspelled path would fail open. The build would write the file and report success.

The build runs layout loaders. A guard reads a cookie, and the build refuses to write a page that reads a cookie. But nothing runs app/server.js during a build. So you must declare a guard in it with gated.

Trailing slashes

trailingSlash sets both the router mode and the redirect.

Value Result
'never' One URL per page. /about/ redirects with a 301.
'ignore' Both URLs return 200.

With 'ignore', one page has two URLs. So say which URL is the main one. Set canonical: true in the config, and every page gets a <link rel="canonical">. The loose router removes the trailing slash before it passes on the path. So the tag names the same URL for both.
