Ethical Web Principles is a W3C Statement from December 2024. It describes what web technology should do for the people using it.

Most of what follows was chosen for other reasons. Sending HTML and shipping no script is a decision about how a page should work, and it happens to answer four of the twelve.

The principle What this framework does
There is one web A page is HTML at a URL. Nothing here reads a country, and the build writes one set of files for everybody.
The web does not cause harm to society No telemetry, no analytics and no install script. This package reports nothing anywhere.
The web supports healthy community and debate A code of conduct, a contributing guide and a security policy, in the repository.
The web is for all people A page carries no bundle, so a slow network and an old phone still get the text. See accessibility and languages.
The web is secure and respects people's privacy A policy built from the hashes of what a page inlines, cookies that are HttpOnly and SameSite=Lax, and a refusal to fetch a private address. See security.
The web enables freedom of expression The build writes a directory any static host serves. No account and no service sits between you and a reader.
The web makes it possible to verify information Nothing minifies the HTML. What a reader sees in view source is the page you wrote.
The web enhances individuals' control and power MIT, five dependencies, four runtimes. Nothing here needs a company to keep running.
The web is an environmentally sustainable platform No client entry unless a page asks for one, and no prefetching unless you turn it on. A test holds the count.
The web is transparent This site serves its own source, and the refusals page is read out of the compiler rather than written by hand.
The web is multi-browser, multi-OS, and multi-device Five platform features carry a date, and the rest is markup. See browsers and runtimes.
The web can be consumed in any way that people choose An element renders into the page's own DOM, so a user stylesheet, an extension and reader mode all reach it.

What makes the last one true

A shadow root hides content from a user stylesheet, from some extensions and from some reader modes. This framework makes the shadow root the opt-in and the page's own DOM the default.

Navigation is the other half. There is no client router, so back, forward, find in page and open in new tab work because nothing replaced them.

Where this falls short

An element with styles needs a 2026 browser. Those styles are scoped with @scope, and browsers agreed on it in March 2026. A browser without it drops the block and the element renders unstyled. The browsers page says what to do about that.

Two headers are off by default. csp and permissionsPolicy each take something away from an app that may want it, so both stay yours to set. A generated project turns both on, which is where the decision can be read.

There is no message catalog. Routing and Intl cover a multilingual site, and this package ships neither a catalog format nor a fallback chain. Languages says why.

A widget's keyboard behavior is yours. The framework renders the markup you wrote and adds no roles. A tab list or a menu is a contract with a keyboard, and nothing here writes one for you.
