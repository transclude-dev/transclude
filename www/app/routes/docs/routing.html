Drafts

A page in the tree is a route, which leaves nowhere to put one that is not finished. This is that.

${html(s.draft)}

npm run dev serves it, because the dev server reads the directory. The build leaves it out: no file, no route in the manifest, no line in the sitemap. The deployed site answers that URL with the not-found page. Publishing is deleting the line.

A page absent from production and silent about it is a bad afternoon, so every build prints its drafts under everything it wrote. If you deploy and a page is missing, the reason was on screen when you built it.

Being in dev and not in production is a difference, and differences like it are where the quiet bugs live. This one is the whole point of the feature, which is why the build is loud about it.

The loader

A <script server> block runs on the server. Its default export takes the request context and returns the data the markup reads.

${html(s.loader)}

A page that reads nothing needs no block at all. Leave it out rather than exporting a loader that returns an empty object.

The loader and the markup that reads it change together, so they are one file to open and one file to review. The block is compiled into the route and never reaches the browser. Why transclude makes the longer case.

The context

Field What it is
absolute absolute('/og.png') against metadataBase.
action What this page's action returned, if one ran.
cookies Read and write, signed or plain.
fragment The fragment asked for, or null.
params The path segments this route captured.
request The Request. null while prerendering, which is the only time there is none.
response The status and headers for the response.
route The matched route, including its path.
url The full URL, as a string. new URL(url) for its parts.

Tags that move into <head>

Write <title>, <meta>, <link> or <base> at the top level of a page and it is moved into <head>. A page keeps its head next to the markup that needs it.

${html(s.head)}

A directive on one of them works, and the tag still lands in <head>. The condition is written there with it, so a <link> whose condition is false is not sent at all.

Which level's title wins is settled when the page compiles, by whether a level has one at all. A condition would make it a question only the request can answer. A false one would leave the page with no title, and the layout's already ruled out. Interpolate the text instead.

Interpolation

\${…} reads what the loader returned and is always escaped, so a value carrying <script> arrives as text. html() is the one way out, and it is in scope in every file with nothing to import.

${html(s.interpolation)} It marks a value as markup you vouch for. It sanitizes nothing, so html() around anything a visitor typed is how a page runs somebody else's script. Security has the rest.

In an attribute

An attribute value takes ${empty} too, whole or in part, as many times as you like.

${html(s.attributes)}

The value is escaped by attribute rules, which are not the text rules. What a value is decides what the attribute becomes.

The value The attribute
false, null, undefined dropped, rather than written as a string
true the name on its own, as disabled
an object or an array JSON, which is how an element reads it back
anything else the string, escaped
Only a value is read. An interpolation in the attribute name is a compile error, because emitting it would put ${empty} into the page as those characters. To pick between two spellings, put the condition in the value.

Directives

Four attributes decide whether an element renders and how many times. They are the whole templating language.

Directive What it does
if="expr" Render this element only when the expression is true.
else-if="expr", else Continue the chain from the element before.
each="item of list" Render this element once per item.
key="expr" Which item is which, across a re-render.

A directive's value is an expression, not a string. There is no ${empty} inside one, and no quotes around a name: if="query" reads the field called query.

if, else-if, else

The first one whose expression is true renders. The others are left out.

${html(s.loopScope)} Not an empty row and not a message. If a list has something to say when it is empty, that is an if beside it. ${html(s.loopEmpty)}

key

key says which item is which, so a re-render can move a row rather than rewrite it. Input values, focus and scroll position survive a reorder.

${html(s.keyed)}

It matters where something re-renders in the browser, which is a shadow element. A page is rendered once per request, so a key there changes nothing.

What is refused

Each of these is a compile error with a line number.

${html(s.refused)} Sorting, filtering and formatting are the loader's job. A template decides what appears, not what the data is. It is also what makes the names a page reads collectible, which is where the type checking comes from.
