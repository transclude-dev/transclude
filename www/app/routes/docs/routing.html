Drafts

Every page in the tree is a route. To keep an unfinished page out of production, mark it as a draft.

${html(s.draft)}

npm run dev serves a draft, because the dev server reads the directory. The build leaves it out. It writes no file, no route in the manifest and no line in the sitemap. The deployed site answers that URL with the not-found page. To publish the page, delete the line.

A page that is missing with no message is hard to find. So every build prints its drafts after the list of files it wrote. If a page is missing after you deploy, look at the build output. The reason is there.

A page that is in dev but not in production can cause bugs that are hard to see. For a draft, that difference is the purpose of the feature. So the build reports it clearly.

The loader

A <script server> block runs on the server. Its default export takes the request context and returns the data the markup reads.

${html(s.loader)}

A page that needs no data needs no block. Leave the block out. Do not export a loader that returns an empty object.

The loader and its markup change together. So they are in one file, and you open and review one file. The block is compiled into the route, and the browser never gets it. Why transclude gives the full reasons.

The context

Field What it is
absolute absolute('/og.png') against metadataBase.
action What this page's action returned, if one ran.
after Takes a promise. The response does not wait for it. See runtimes.
cookies Reads and writes cookies, signed or plain.
fragment The fragment asked for, or null.
layout The data that the loaders above this one returned, merged. See layouts.
params The path segments this route captured.
request The Request. It is null only while prerendering.
response The status and headers for the response.
revalidateTag Removes every cached page that has a given tag. See the production build.
route The matched route, including its path.
url The full URL, as a string. new URL(url) for its parts.

Tags that move into <head>

You can write <title>, <meta>, <link> or <base> at the top level of a page. The tag then moves into <head>. So the head tags stay next to the markup that needs them.

${html(s.head)}

You can put a directive on one of these tags. The tag still moves into <head>, and its condition moves with it. So if the condition on a <link> is false, the server does not send that <link>.

The compiler decides which level's title wins. It checks only whether each level has a title. A condition would make the answer depend on the request. A false condition would leave the page with no title, because the layout's title already lost. Interpolate the text instead.

Interpolation

\${…} reads the data that the loader returned. Its output is always escaped, so a value that contains <script> shows as text. html() is the only way to skip the escaping. You can use it in every file, with no import.

${html(s.interpolation)} html() marks a value as markup that you trust. It does not sanitize anything. If you put html() around text that a visitor typed, your page can run another person's script. Security has more.

In an attribute

An attribute value can also contain ${empty}. It can be the whole value or a part of it, and it can appear many times.

${html(s.attributes)}

The value is escaped with attribute rules, which are different from the text rules. The type of the value decides what the attribute becomes.

The value The attribute
false, null, undefined removed, not written as a string
true the name on its own, as disabled
an object or an array JSON, so an element can read it back
anything else the string, escaped
An interpolation works only in a value. An interpolation in the attribute name is a compile error. Otherwise the page would contain the characters ${empty} as they are. To choose between two spellings, put the condition in the value.

Directives

Four attributes decide if an element renders, and how many times. These four are the complete templating language.

Directive What it does
if="expr" Render this element only when the expression is true.
else-if="expr", else Continue the chain from the element before.
each="item of list" Render this element once per item.
key="expr" Identify each item across a re-render.

A directive's value is an expression, not a string. Do not put ${empty} inside it, and do not put quotes around a name. if="query" reads the field called query.

An expression can read data and call functions. It cannot contain an assignment, an arrow function, an object literal or await. Do that work in <script server>, and return the result. ${empty} uses the same grammar. Decisions and limits explains why the grammar is small.

The elements in a chain must be next to each other. Whitespace and comments between them are allowed. Any other element ends the chain. An else with no if before it is a compile error. It does not become an element that never appears.

each

The element repeats once for each item. Inside it, the item is in scope.

${html(s.loopOut)}

You can use the name everywhere inside the element, including its attributes. A loop inside another loop can read the name of the outer loop.

${html(s.loopScope)} It renders no empty row and no message. To show a message for an empty list, put an element with if next to the loop. ${html(s.loopEmpty)}

key

key identifies each item. So a re-render can move a row instead of writing it again. Input values, focus and scroll position stay the same when the order changes.

${html(s.keyed)}

A key matters only where markup re-renders in the browser. That happens in a shadow element. A page renders once per request, so a key in a page changes nothing.

What is refused

Each of these is a compile error with a line number.

${html(s.refused)} Do sorting, filtering and formatting in the loader. A template decides what appears. It does not change the data. This rule also lets the compiler collect the names that a page reads. The type checking uses those names.
