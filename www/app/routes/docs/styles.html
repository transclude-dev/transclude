What crosses a shadow boundary

  • Custom properties inherit. So --rule on :root gets inside a shadow root.
  • Selectors do not. A global class applies to a page and to a light element, but it stops at a shadow root.

So a global stylesheet themes a shadow element through custom properties. To let the stylesheet style a node inside, the element marks that node with a part attribute. ::part() then selects it. The element decides which nodes it exposes.

Styles in a file

A <style> block in a page or layout moves into <head>. In an element, the block is scoped to that tag. Use :scope to style the element itself.

${html(s.scoped)}

Styles for swapped-in markup

An element that arrives in a fragment brings its styles with it. The styles go into <head> one time, automatically. You do not set anything up.

The element itself

You style a light element with :scope and a shadow element with :host. Both mean the element that the stylesheet belongs to.

${html(s.selectors)}

The difference is which rules can override them. :scope rules move into <head>, inside the transclude cascade layer. Page CSS beats a layered rule at any specificity. So a page can override a light element that it did not write. :host rules stay inside the shadow root. A page rule on the host element beats them, but no page rule reaches the nodes inside. :host has very low specificity, so a rule inside the element beats it.

View transitions

Cross-document view transitions use only CSS, and they are off until you turn them on. Both documents must contain the rule.
