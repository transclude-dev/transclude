transclude/production is the same app npm start serves. Importing it gives you a request method that takes a URL and answers the way the server does.

${html(s.request)}

Everything a browser would meet runs: the trailing-slash redirect, CSRF, your own middleware, cookies, the cache and the route table. A test that passes here is about the site rather than about a copy of it.

It reads a build

The app is assembled from dist, so run npm run build first. Skip rather than fail when there is no build, and a fresh clone still gets a useful npm test.

${html(s.guard)}

The server's environment is not the test's

npm start passes --env-file-if-exists=.env. node --test does not, so a secret the config reads is missing, and the first page that touches a signed cookie answers 500. Either add the flag to the test script, or set the value before the first import.

${html(s.script)} ${html(s.env)}

What to ask for

A form post is a real post. Give it an origin, or CSRF refuses it, which is itself worth a test.

${html(s.form)}

A fragment is a URL, so it is read the same way. The useful assertion is that the page and the fragment agree, since one compiled template produces both.

${html(s.region)}

What this does not reach

Anything that needs a browser: an element upgrading, a shadow root, focus surviving an update, a swap. Nothing in Node models those, and a test that says otherwise is describing its own stand-in.

Put those on a page and open it. The showcase keeps its own at /check, which runs its assertions in the browser and posts the result back. Its CI drives that page with headless Chrome on every push.
