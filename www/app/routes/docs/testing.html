transclude/production is the same app that npm start serves. When you import it, you get a request method. It takes a URL and returns the same response that the server does.

${html(s.request)}

Every step that a browser request goes through also runs here. This includes the trailing-slash redirect, CSRF, your own middleware, cookies, the cache and the route table. A test that passes here tests the real site, not a copy of it.

It needs a build

The app loads from dist, so run npm run build first. If there is no build, skip the tests instead of failing them. Then npm test is still useful in a fresh clone.

${html(s.guard)}

The server and the tests have different environments

npm start passes --env-file-if-exists=.env. node --test does not. So a secret that the config reads is missing. Then the first page that uses a signed cookie returns 500. Add the flag to the test script, or set the value before the first import.

${html(s.script)} ${html(s.env)}

What to ask for

A form post in a test is a real post. Give it an origin, or CSRF refuses it. That refusal is also worth a test.

${html(s.form)}

A fragment has its own URL, so you read it the same way. One compiled template produces both the page and the fragment. So check that the two agree.

${html(s.region)}

What these tests cannot check

They cannot check anything that needs a browser. Examples are an element that upgrades, a shadow root, focus that stays after an update, and a swap. Node does not model these. A test that says it does is testing its own fake version.

Put those checks on a page and open it in a browser. The showcase has its own checks at /check. That page runs its assertions in the browser and posts the result back. Its CI opens that page in headless Chrome on every push.
