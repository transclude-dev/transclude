${html(s.check)}

With no annotations, it catches a misspelled field in a template, an unknown prop on an element, and a prop with the wrong type.

typecheckStrict: true turns on full TypeScript strictness. This also requires a declared type on every parameter.

Where the types come from

  1. The type of the loader's return value.
  2. The types that properties and state declare in <script element>.
  3. JSDoc, where inference is not enough.

Attributes that are not props

data-*, aria-* and hx-* pass through. They are still checked as expressions, so ${passThrough} on an element is not an error.

This file is generated from the compiled routes. It is written to the path that typesFile names. It is an output, so add it to .gitignore.

In your editor

A new project turns off one setting in .vscode/settings.json:

${html(s.editor)}

Here, a .html file contains script blocks that are separate modules. A page with a <script server> and a client <script> has two modules. Each has its own top-level names, and that is correct. But the editor's built-in HTML support reads every block as one module. So it reports the duplicate names as a mistake.

You lose nothing when you turn it off. npm run check reads these files the same way the compiler does. So does the language server in the package's editor/ directory.

A VS Code extension is in the package's editor/vscode directory. It starts that server for any workspace with a transclude.config.js. It also highlights ${'$'}{…} as an expression. The server comes from the package installed in your project, so the diagnostics match the version you build with. The extension's README tells you how to package and install it.

While you work

npm run dev checks in the background and prints what it finds. The page still compiles, and the server still sends it. You see a type error, but it does not stop you.

On every run, it says how many files it read, even when the run is clean. If a checker prints only on failure, a run that passed looks the same as a run that never happened.

Set typecheck: false to turn it off. Without TypeScript installed, it does nothing, and it says so once at startup.

The setting comes from the project scaffold. The framework does not apply it. So if your project does not have the file, write it by hand. Without it, you see "A module cannot have multiple default exports" on every element with props and state.
