With no annotations it catches a misspelled field in a template, an unknown prop on an element, and a prop given the wrong type.

strict: true turns on full TypeScript strictness, which also wants a declared type on every parameter.

Attributes that are not props

data-*, aria-* and hx-* pass through. They are still checked as expressions, so ${passThrough} on an element is not an error.

In your editor

A new project turns off one setting, in .vscode/settings.json:

${html(s.editor)}

A .html file here holds script blocks that are separate modules. A page with a <script server> and a client <script> has two of them, each with its own top-level names, which is correct. The editor's built-in HTML support reads every block as one module and reports the overlap as a mistake.

Nothing is lost by turning it off. npm run check reads these files the way the compiler does, and so does the language server in the package's editor/ directory.

A VS Code extension in the package's editor/vscode directory starts that server for any workspace with a transclude.config.js. It also highlights ${'$'}{…} as the expression it is. The server comes from your project's own installed package, so the diagnostics match the version you build with. Its README says how to package and install it.

The setting is scaffolded, not applied by the framework, so a project made before this needs the file written. The symptom is "A module cannot have multiple default exports" on every element with props and state.
